# Local file converter

The converter runs offline and writes a new user-approved output. Its eight-category catalog displays unavailable adapters with explicit reasons. Included runtime adapters format JSON, normalize UTF-8 text, encode exact bytes as Base64 or hexadecimal, list/extract/repack supported ZIP files, and convert string tables between CSV, TSV, JSON, XLSX and ODS. See [spreadsheet table conversion](spreadsheets.md) for limits and disclosures. PDF support requires the packaged `pdf-lib` 1.17.1 proof supplied by the main process; installing a tool on PATH never enables an adapter.

## Workflow and integration

`createConverterService({stateDirectory, resolveGrant, bundledProof, sandboxProvider})` is main-process-only. `resolveGrant(id, mode)` resolves an opaque, user-approved source or destination capability. Do not pass renderer paths or accept arbitrary IDs. Expose only catalog, inspect, enqueue, list, and control through validated IPC. On startup call run, and on exit close. `mountConverter(root,{services,translate})` expects those methods under services.converter plus pickSources, pickDestination, and confirmOverwrite.

Each queue item has at most 32 sources, a 64 MiB total input budget, 128 MiB output budget and 30-second worker timeout. The queue itself has no total item limit: separate durable records are streamed from disk and history is paged in groups of at most 50. One item runs at a time. Interrupted running records become paused, requiring explicit resume and source revalidation. Grants must survive restart securely or resumed work fails safely. JSON formatting, metadata changes, and text normalization may change representation as disclosed by each adapter. Preview text is limited to 2 KiB.

Execution is disabled unless the main process supplies a trusted sandboxProvider with verifiedOsIsolation=true and a launch method. The native provider is created by createWindowsSandboxProvider with package-manifest hashes for the launcher, its present DLL/runtimeconfig/deps companions, and standalone Node executable. It performs a real conversion probe before declaring isolation available. The included restricted-process helper starts a real child process with Node permissions, no filesystem writes, no network, no process or worker creation, no native addons, a constrained heap and a deadline. It receives only bounded byte buffers, not source paths. It probes these capabilities and rejects older runtimes that cannot deny network. Node permissions are defense in depth, not an operating-system security boundary against a compromised runtime. The native launcher creates a fresh AppContainer without network capabilities, verifies the child token, assigns the suspended child to a one-process memory-limited job, and resumes it only after those checks. The isolated profile and job are removed before a successful receipt is accepted. Unit-test providers simulate this integration contract and do not constitute OS isolation evidence. The main process retains file authority. Output staging uses same-directory temporary files and a no-replace hard link unless replacement was explicitly confirmed. Source paths are compared before every write. Split requires an explicit destinationDirectoryId resolved with directory mode. Every generated name is checked, all target paths are preflighted before publication, and folder output replacement is prohibited. A competing writer during publication can still cause a later publication to fail; the result explicitly lists any complete outputs that remain, but no partial file is exposed. Source data is never modified.

The PDF adapter documents its exact operations and rejects opaque encrypted or signed documents. Output bytes are reopened and validated before publication. Media conversion requires its verified packaged runtime. 7z/RAR remains unavailable until its bundled adapter and isolation evidence exist.

## Verification

Run `node --test test/converter-*.test.js`. These checks cover actual byte conversion and PDF operations. Packaged UI, keyboard, localized copy, filesystem capability persistence, and OS isolation require integration verification before a release claim.

## Remaining operating-system boundary

The restricted child uses only the selected absolute runtime, never PATH discovery. The host must supply a packaged OS sandbox launcher and verify its identity, resource policy, no-network token and allowed code read paths. The C# launcher source is supplied under native/. The host must build and package it and a standalone Node executable, then pass their manifest hashes. Production adapters remain disabled if this setup or its real startup probe fails. Source reads and output publication occur in the trusted parent through approved grants. Cancellation state transitions are serialized: a cancellation during source revalidation cannot be replaced by a stale running record, and publication is one bounded critical section.

The native staging layout separates a read-only payload directory from a writable work directory. Only selected source bytes are copied into work. The worker writes numbered output files and a nonce-bound result manifest; the parent validates the launcher receipt, profile deletion, token capability count, result hash, bounded output list, and file lengths before returning bytes to the queue. The parent deletes its temporary staging directory after every outcome. Cancellation uses a bounded signal-file request so the native launcher can kill its job and delete its profile normally.

### Native verification and bounds

Build the native project through the host build entrypoint, then run its native/smoke.ps1 verification and the converter Windows integration tests. The launcher stages no user source paths inside its worker protocol. A fresh profile has zero capability SIDs; the actual child token is checked before resuming the process. The job permits one process, caps process memory at 256 MiB, kills children on close, and enforces a 30-second wall-clock deadline. Work-directory growth is checked every 100 ms against 256 MiB and 2,000 entries; this is a termination monitor, not a filesystem quota. Cancellation also uses the monitor. The worker payload uses the runtime's preserve-symlinks flags so its module loader does not attempt to traverse denied parent directories; the staged tree itself rejects reparse points.

## Quit coordination

pending() streams the complete durable inventory and returns the numeric count of queued or running items, excluding paused work. cancelAll() invalidates outstanding admissions, waits for their bounded reads to settle, cancels every queued/running record across all pages, signals active workers, and waits for native cleanup and durable terminal records. It returns {cancelled, remaining}. Paused work remains available for a later session. close() uses the same cancellation barrier. Publication and cancellation share a per-record lock, so an already completed atomic publication is reported as completed rather than being rewritten as cancelled.
