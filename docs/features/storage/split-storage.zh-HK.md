# 分散存放及鏡像備份

分散存放可以將磁碟嘅加密分段分散放喺幾個地方，例如一半放喺主儲存資料夾、四分一放喺 USB、四分一放喺 Docker Hub。鏡像備份則會保留整個儲存資料夾嘅完整副本，而且可以獨立開啟。你可以由「本機工具」、「Docker Hub 儲存」頂部嘅連結，或者喺指令面板同「新增分頁」目錄搜尋「鏡像備份」，開啟「分散存放」。

每個位置都只存放密文，即係 `parts/` 入面現有嘅位元組。分散嘅單位係一個完整嘅加密分段，所以「儲存空間維護」入面嘅「分段大小」設定，決定到分得幾細。

## 邊啲嘢放喺邊度

- **主儲存資料夾**永遠保留 `vault.json`、`commits/` 同 `activity/`。中繼資料唔會離開主資料夾去到分配位置。
- 每個分配位置收到嘅係完整分段。資料夾會寫入 `<folder>/MaterialFileEncryptor-Split/<drive id>/parts/`，同時有一份 `placement.json`，令資料夾可以自我說明。Docker Hub 就用獨立嘅快照標籤存放佢嘅份額。
- 主儲存資料夾入面嘅 `placement.json` 記錄分段編號、大小、位置編號、你設嘅名稱同設定。分段編號同大小喺 `parts/` 本身已經睇到，所以唔會多洩露明文。**名稱任何可以讀取儲存資料夾嘅人都睇到**，請唔好喺名稱入面寫機密。

## 設定 USB 分配

1. 開啟「分散存放」，選「新增磁碟或 USB 位置」。
2. 選「選擇資料夾…」，揀 USB 上面嘅一個資料夾。喺主儲存資料夾、快取資料夾或者已掛載磁碟代號入面嘅資料夾會被拒絕。
3. 設定名稱，例如 `USB backup (E:)`，再設定「分配比重」。主位置比重係 2、USB 係 1，USB 就會得到三分一嘅分段。每個位置旁邊嘅百分比同分配條會隨你輸入即時更新。
4. 可以另外設定「容量上限」，計劃唔會分配超過上限。
5. 按「預覽」。計劃會顯示要搬移幾多分段同位元組，以及某個位置斷開連接時邊啲檔案會打開唔到。
6. 按「儲存設定」，再按「開始分散」。未按開始分散之前，唔會搬移任何嘢。

## 新增 Docker Hub

按「新增 Docker Hub」，用細楷輸入 `owner/name` 格式嘅儲存庫。請先喺 Docker Hub 儲存頁面登入。只會上載密文，每個分段係一個內容定址嘅層。因為只有密文移動，所以容許公開儲存庫。正如[儲存庫備份文章](registry-sync.zh-HK.md)所講，公開儲存庫入面如果有 `vault.json`，就可以離線猜密碼。呢個功能永遠唔會將 `vault.json` 上載到分配位置，所以分散存放唔會增加呢個風險。不過 Docker Hub 鏡像備份係包含 `vault.json` 嘅，請使用金鑰檔或者夠長嘅密碼句。

## 副本同分散

「每個分段嘅副本數」決定每個加密分段存放喺幾多個不同位置。

- **1 個副本**係純分散。**要打開存放喺某位置嘅檔案，就一定要連接嗰個位置。**如果 USB 被拔走，存放喺嗰度嘅檔案要等重新連接先打開到。
- **2 個或以上副本**會喺不同位置存放額外副本。冗餘要用更多空間：兩個副本大約需要兩倍總空間。

## 規則

規則可以將符合樣式嘅檔案固定放喺某個位置，例如 `Projects/**` 放主資料夾、`*.mp4` 放 USB。先符合嘅規則優先。幾個檔案共用嘅分段，跟路徑次序最前嗰個檔案。冇符合規則嘅就按比重分散。規則可以指向分配位置，但唔可以指向鏡像。

## 安全備份

「安全備份：分散完成前，所有資料都保留喺主磁碟」預設開啟，連未有呢個設定嘅舊設定檔都會當作開啟。

開啟時，開始分散嘅工作分幾個階段，你可以喺工作進度睇到：

1. **複製分段**：新副本寫入、同步到磁碟並以 SHA-256 核對期間，所有分段都留喺主資料夾，任何地方都唔會刪除嘢。
2. **驗證副本**：最後再讀一次所有目標副本。
3. **釋放主磁碟空間**：只有所有計劃內嘅副本都驗證成功，先會移除主磁碟上已唔屬於嗰度嘅分段副本，而且每個移除前都會再確認新副本仍然存在並通過驗證。

如果複製失敗、某位置斷開連接，或者你喺頭兩個階段取消，釋放階段就唔會執行。頁面會顯示「分散未完成，你嘅檔案仍然全部喺主磁碟」、原因同「重試」按鈕。重試會由已驗證嘅副本繼續。工作被擱置期間，讀取會優先用主磁碟嘅副本。

關閉安全備份要喺對話框確認。關閉之後，每個分段一驗證到新副本就會即時由主磁碟移除，分散期間主磁碟唔再有完整副本。如果 USB 中途出事，部分檔案要等嗰個位置重新連接先打開到。目標位置一定要有足夠空間放自己嘅全部份額，開始複製前會先檢查。

## 拔走磁碟會點

任何位置都唔會刪除嘢。該位置會顯示「未連接」，只存放喺嗰度嘅檔案會喺計劃入面列為打開唔到，直至你重新連接。打開嗰類檔案時會見到點出位置名稱嘅訊息，例如「呢個檔案存放喺 USB backup (E:)，而佢未有連接。」重新連接磁碟再打開檔案就得。斷開連接嘅位置永遠唔會引致移除。

## 鏡像備份

**鏡像**會保留磁碟加密儲存資料夾嘅完整副本：所有分段加埋 `vault.json`、`commits/` 同 `activity/`，結構同一個儲存資料夾完全一樣，位於 `<folder>/MaterialFileEncryptor-Mirror/<drive id>/`。鏡像唔參與比重、副本或規則，唔計入分散副本，而且關閉分散存放後都照常運作。

1. 選「新增鏡像資料夾」或「新增 Docker Hub 鏡像」，揀目的地。鏡像資料夾可以喺同一個磁碟嘅另一個資料夾。
2. 按「儲存設定」，再按「即時更新鏡像」。

如果鏡像同主儲存喺同一個磁碟，會見到呢段說明：「呢個位置同你嘅主儲存喺同一個磁碟，所以可以防止誤操作，但係防唔到嗰個磁碟壞咗。」要防硬件故障，請用另一個磁碟或者 Docker Hub。

每個鏡像都會顯示名稱、路徑、連接狀態、上次更新時間，以及「已係最新」或者「由某時間起已過期」連同落後嘅分段數同位元組。鏡像會喺每次成功分散後、磁碟有改動並閒置一陣後，以及你按「即時更新鏡像」時更新。未連接嘅鏡像會略過，重新連接後自動追上。更新次序係先複製並驗證新分段，再寫入中繼資料（最後先寫 `vault.json`），最後清走磁碟唔再引用嘅分段，所以鏡像永遠唔會收到不完整嘅中繼資料。鏡像上嘅「驗證」會重新讀取副本，並報告損毀或缺少嘅分段。

## 由鏡像還原

如果主磁碟遺失，可以將鏡像獨立當作一個磁碟開啟：

1. 連接放有鏡像嘅磁碟，或者連到 Docker Hub 儲存庫。Docker Hub 鏡像要先喺「Docker Hub 儲存」還原。
2. 喺呢個頁面按「由鏡像開啟磁碟…」，或者喺主視窗按「解鎖現有磁碟」。
3. 揀 `MaterialFileEncryptor-Mirror/<drive id>` 資料夾做儲存資料夾，再用平時嘅密碼或金鑰檔解鎖。

鏡像會當作一般儲存資料夾讀取。請另外揀一個新嘅快取資料夾。解鎖時仍然會驗證磁碟金鑰同加密中繼資料。

## 全部搬返主位置

「全部搬返主位置」會用同樣嘅先驗證後刪除次序，將所有分段搬返主儲存資料夾。佢會結束分散，但保留你嘅設定同鏡像。

## 安全注意事項

- 只有密文會離開主儲存資料夾，中繼資料檔案唔會搬去分配位置。
- 名稱同 `placement.json` 入面嘅分段編號，任何可以讀取儲存資料夾嘅人都睇到。
- 只有喺替代副本存在、已寫入磁碟並逐位元組驗證通過之後，先會由某位置移除分段。任何分段嘅最後一個已驗證副本永遠唔會刪除，中斷咗嘅搬移可以繼續。
- 只會喺引擎對來源閒置時重新平衡。

## 驗證狀態

呢個頁面係 `splitStorageStatus`、`saveSplitStorage`、`previewSplitStorage`、`applySplitStorage`、`cancelSplitStorage`、`disableSplitStorage`、`verifySplitStorage`、`updateMirrors` 同 `verifyMirror` 呢啲主機方法嘅前端。如果版本冇提供，頁面會顯示呢個版本暫時未有分散存放功能，而且唔會顯示任何資料。畫面同互動由 `test/split-storage-panel.test.js` 用模擬狀態物件測試。真正傳輸到 USB 或 Docker Hub，仍然需要喺已建置同安裝嘅程式另行驗證。
