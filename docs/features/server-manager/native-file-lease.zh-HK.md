# 原生伺服器檔案租約基礎元件

`ServerFileLease.Acquire` 接收可信工作階段擁有嘅伺服器根目錄、已准入伺服器 JAR 嘅 SHA-256，以及獨立批准嘅執行環境根目錄、執行檔路徑同 SHA-256。佢唔會探索或接管現有伺服器、批准執行環境，亦唔會向呈現器提供任意檔案 API。

喺 Windows，呢個元件會用拒絕刪除共用嘅原生 handle 固定每一層目錄。重新解析點、唔符合預期嘅最終 handle 路徑、非一般檔案同多重硬連結檔案都會被拒絕。元件只允許讀取共用，開啟精確 JAR 同執行檔，再對持有中嘅檔案計算雜湊，保留受保護嘅重複 handle。現有寫入者會阻止准入；租約持有期間，新嘅寫入、改名同刪除操作會被阻止。呢啲共用保證唔代表可以阻止預先存在嘅可寫入記憶體映射。

`AssertHeld` 檢查保留嘅原生 handle。`Release` 需要明確呼叫，而且可重複安全呼叫。遇到程序擁有權未知、逾時或 IPC 結果未明，生命週期擁有者必須保留物件；只有證明程序未啟動，或者精確專用程序已退出，先可以釋放。部分准入失敗只會關閉今次嘗試建立嘅 handle，唔會刪除或覆寫檔案。程序終止自然會關閉作業系統 handle，所以呢個元件本身唔係可以跨崩潰保留嘅監督服務。

原生元件尚未接駁 `LocalProcessServerAdapter` 或主機 IPC。可信擁有權登記、執行環境批准、請求身份、逾時復原，以及跨 IPC 生命週期保留仍然待完成。轉接器預設檔案租約服務仍然不可用。

根目錄建置只編譯 `MaterialFileEncryptor.ServerLease.Verifier`，唔會執行佢。輸出會獨立上載，亦會從應用程式套件同 ASAR 內容排除。覆核者會用 `--fixture-root` 同全新、明確指定嘅合成目錄執行已編譯檔案。驗證器保留檔案同 `receipt.json`，涵蓋 handle 共用、上層目錄替換、未知擁有權保留、明確釋放、部分准入、現有寫入者、執行環境路徑範圍同真實 Windows junction。編譯、下載執行檔身份同實際驗證器執行，各自有獨立結論。呢個單元唔代表真實 Java 伺服器、完整管理器或 GUI 已通過驗收。

已編譯驗證器亦會建立可寫入映射、關閉原本檔案 handle，再嘗試准入同修改。收據會分開記錄准入被拒絕，或者持有共用租約期間仍觀察到映射修改；兩種結果都唔會靜靜變成位元組不可變保證。
