# 預先保留正常退出驗證所需的程序控制代碼

`scripts/owned-exit-handle-keeper.py` 係只供驗證使用、持續運作的輔助程序。佢唔會啟動、關閉或終止目標應用程式。佢保留不可繼承的 `PROCESS_QUERY_LIMITED_INFORMATION | SYNCHRONIZE` 控制代碼，避免預先進行正常退出驗證期間，已記錄的確切程序識別碼被重用。佢唔會解釋歷史失敗，亦唔會接納之前被拒絕的證據。

先執行原有配接器的 `prepare-exit`。以隱藏子程序啟動輔助程序，使用管道標準輸入／輸出、選定的直接 CLI 環境，以及以下參數：

```text
--state <canonical-owned-run-root>/lifecycle.json
--helper-sha256 <reviewed-helper-sha256>
--script-sha256 <reviewed-sidecar-sha256>
--source-commit <reviewed-source-commit>
--receipt <canonical-owned-run-root>/exit-handle-keeper.json
--timeout 90
```

輔助程序透過現有直接傳輸投影、原有退出證明政策、祖先關係及確切身份比較，驗證已安裝的生命週期狀態。取得控制代碼前後，實際完整程序樹都必須恰好包含證明中的身份。每個原生控制代碼的 PID 及新取得的 CIM 身份必須同原有證明完全一致，唔設時間誤差容許值，亦唔會正規化路徑。部分取得唔算準備完成；失敗時會釋放所有已取得的控制代碼。

等候 `HANDLES_READY`，再由外部真正關閉瀏覽器。傳送確切內容 `{"command":"confirm"}`。輔助程序會保留全部已取得的控制代碼，用來源綁定的 Python 執行檔執行原有、雜湊綁定且未改動的配接器 `confirm-exit`。必須實際退出碼為零、原有不存在／桌面旗標成功，以及額外未改動的 `_recorded_tree_absent` 結果成功。只容許原有配接器將生命週期由 `cleaned:false` 變成 `cleaned:true`；輔助程序永遠唔會寫入生命週期或退出證明狀態。

收到 `ORIGINAL_CONFIRM_VERIFIED` 後，傳送確切內容 `{"command":"release"}`。成功要求最終輸入未改動、原有不存在判斷為真，以及全部所屬原生控制代碼成功關閉。呼叫方提供的成功旗標唔可以取代原有驗證。EOF、無效指令、到期或任何失敗，都會關閉所屬控制代碼並回報不接納。原生控制代碼關閉失敗會記錄為失敗；程序退出時由作業系統最後清除控制代碼表。期限會喺有界身份／傳輸操作之間及等候指令時檢查；已開始的查詢仍可用盡原有的有界逾時。

標準輸出只包含中性代碼及數量，唔會轉送擷取到的配接器輸出。獨佔的私人收據會透過已安裝輔助工具的禁止連結檢查及已固定目錄，喺原有標準執行根目錄內寫入並讀回。收據綁定原有／最終生命週期雜湊、未改動的證明及身份、輔助工具、旁路程序、配接器、政策、傳輸、Python 雜湊、來源提交，以及保留期間事件。由於包含確切身份及機器路徑證據，收據必須保持私人。現有收據永遠唔會被覆寫。

離線測試涵蓋確切完整程序樹的所有權、CIM／原生取得競爭、部分取得、輸入變更、初始祖先關係拒絕、指令次序、真實配接器退出行為、不存在判斷、逾時、EOF 及控制代碼釋放失敗。呢啲測試唔代表瀏覽器執行期已獲接納。新瀏覽器執行仍須另行授權並經原有關閉驗證。

## 失敗嘗試的診斷與保留

失敗收據只保留有界階段識別碼、例外類別名稱，以及最多八個投影呼叫位置。診斷區塊排除例外訊息、堆疊來源行、任意機器路徑及身份內容。標準輸出繼續只包含中性代碼及數量。冇呢啲診斷的一般歷史失敗仍然原因未明；之後成功的查詢唔能夠還原當時遺失的例外。

預設 `exit-handle-keeper.json` 維持獨佔，永不覆寫。另獲授權的嘗試可以喺完全相同的標準生命週期根目錄使用 `exit-handle-keeper-<32 lowercase hexadecimal characters>.json`。原有收據、生命週期狀態及退出證明全部保留。新嘗試必須獨立通過原有所有權、身份、祖先關係、完整程序樹、不存在及釋放檢查。新檔名唔會取代接納條件，亦唔會授權關閉瀏覽器。
