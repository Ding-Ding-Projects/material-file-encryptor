# 瀏覽器擴充功能證據同參考比對

兩個腳本會擷取已暫存嘅瀏覽器擴充功能，並將每張擷圖綁定到暫存時嘅確切位元組。
佢哋只會讀取同顯示，唔會簽署、安裝或者發佈擴充功能。

## 組件身份

`scripts/build-browser-extension.mjs` 會寫出 `bundle-receipt.json`，入面記低每個暫存檔案嘅 SHA-256 同大小。
佢亦會計出一個組件身份：將每個暫存檔案嘅 `path sha256` 行排好序之後計 SHA-256，但唔包括
`vendor/provenance.js`（佢負責攜帶呢個身份）同收據本身。身份會儲存喺收據同 `vendor/provenance.js` 入面。
擴充功能工作區嘅「狀態」部分會顯示頭 16 個字元做 **組件指紋**，等人可以將運行緊嘅擴充功能同收據對照。

## 產品證據

`node scripts/capture-extension-evidence.mjs`（加 `--quick` 就只用一個主題、語言同視窗大小）：

1. 重新讀取每個暫存檔案，同 `bundle-receipt.json` 對照，重新計算組件身份，再確認
   `vendor/provenance.js` 攜帶嘅身份一樣。有任何唔同都會停止執行。
2. 將暫存資料夾當做未封裝擴充功能，載入一個新嘅臨時無介面瀏覽器設定檔。用戶自己嘅瀏覽器設定檔一律唔會打開，
   臨時設定檔用完會刪除。
3. 打開工作區主頁、頁面宣告嘅每個部分同彈出視窗，分別用淺色同深色主題、英文、廣東話同雙語，
   工作區用 1280 × 800 同 320 × 568，彈出視窗用 400 × 560 同 320 × 480。
4. 每個狀態都會檢查頁面自己報告嘅資料：文件語言、主題、可見嘅畫面或部分、組件指紋、已載入嘅擴充功能版本、
   有冇橫向捲動，同埋有冇腳本錯誤，然後儲存一張 PNG。
5. 寫出 `out/extension-evidence/<identity prefix>/receipt.json`，入面有組件身份、來源提交、瀏覽器版本、
   每項檢查結果同每張圖片嘅 SHA-256。只要有任何檢查唔通過，結束代碼就唔係零。

收據會寫 `installation: not-performed`：將未封裝擴充功能載入臨時設定檔唔等於喺商店安裝，
呢個腳本亦冇測試過喺商店安裝嘅擴充功能。

## 參考比對

`node scripts/compare-extension-references.mjs`（加 `--quick` 就每個狀態只用第一組設定）：

- 喺 `127.0.0.1` 以唯讀方式提供呢個工作副本（只接受 GET、唔提供隱藏路徑、唔會超出工作副本範圍），
  然後打開 `design/extension-completion/states.json` 入面每個喺擴充功能有對應正式路徑嘅狀態。
- 用同一個視窗大小、裝置縮放、主題同語言，分別顯示參考畫面同已暫存嘅擴充功能，兩張擷圖都會儲存，
  再量度有幾多比例嘅像素喺任何一個顏色通道相差超過 48。
- 擴充功能嗰邊係顯示冇配對桌面時嘅樣。如果參考畫面描繪嘅係要靠桌面先出現嘅狀態，
  都係同擴充功能自己顯示嘅畫面比較，收據會講明。
- 會列出每個喺擴充功能冇正式路徑嘅參考狀態。
- 寫出 `out/extension-reference-parity/<identity prefix>/receipt.json`。收據只報告量度到嘅差異，
  絕對唔會宣稱參考畫面同擴充功能等同。

## 限制

- 呢兩個腳本需要 Microsoft Edge 或者 Google Chrome。想用其他執行檔，就設定 `MFE_EXTENSION_BROWSER`。
- 擷圖留喺 `out/`，唔會提交。發佈擷圖係另一個要經審閱嘅步驟。
- 執行通過只證明以上列出嘅檢查，喺無介面瀏覽器入面對嗰個組件成立。佢唔證明配對咗桌面、喺商店安裝，
  或者喺用戶真實瀏覽器設定檔入面嘅行為。
