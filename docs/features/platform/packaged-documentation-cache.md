# Packaged documentation catalogue reuse

The main process supplies `app.isPackaged` as a trusted input. Only that explicit decision enables a lazy shared read and parse for catalogue and changelog requests. A packaged-looking pathname does not enable reuse. Development requests read fresh content.

Parsed packaged JSON is deeply frozen, read or parse failures permit retry, and closing releases the retained reference and rejects pending or later results. Existing request validation and exit admission remain unchanged. Installing another version requires a new service lifetime. Retaining the parsed catalogue costs memory while avoiding repeated reads and parses.

The main-baseline adaptation includes no newer access, browser or server lifecycle methods. Dedicated tests cover concurrent reuse, mutation rejection, retry, fresh development reads, unsupported actions, close during load and actual feature-service dispatch. At `187364a3094b1f66e5798d10991f2e3d09d40af9`, eight focused checks passed and were independently repeated, the exact root build exited 0, and production bytes matched the ASAR. On the same 7,863,011-byte extracted catalogue, 31 alternating samples measured 17.3215 ms fresh versus 0.0182 ms reused request medians, and 28.5182 ms versus 0.0065 ms concurrent medians. First read/parse/freeze took 24.9591 ms. [Selected public proof](../../evidence/main-performance-20261012.json) retains source and input hashes. These are local Node component measurements excluding IPC and original ASAR access. IPC, renderer speed, installed behavior and visible acceptance remain separate.
