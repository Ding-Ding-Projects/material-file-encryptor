# Optional settings guidance

Guide and Explain appear immediately above their exact target. They stay closed until requested. The original control remains usable through its real validation, locks, authentication, confirmation, history and action. Back preserves the live draft; Cancel stops guidance without claiming rollback.

## Source and verification boundary

Each stable concept below is authored once in the shared settings inventory and field/action behavior records. Live help reads the real offered choices and typed default, and distinguishes stored preferences, compiled defaults and unsaved drafts. It never reads a secret value. Changing a schedule setting refreshes the Value type and default.

Focused checks mount the actual settings renderer in a DOM fixture and drive the real settings and encrypted-history consumers. They are not native/browser acceptance or capture evidence. Nested editors, read-only elements and advanced search guidance remain pending; this is not product-wide completion.

## Confirmation and async lifetime

Reset uses the native reset adapter when supplied. Otherwise the shared fallback uses the real approval-only two-key/full-slider confirmation. Pagehide, authentication loss and destruction invalidate approval; the store still rejects unauthorized mode transitions. Confirmed changed settings record once in authenticated unlocked history. Next admits one pending validation, rechecks availability after awaiting and ignores cancelled continuations. Back restores focus; disposed work cannot focus a replacement by an old ID. Clear awaits the original admitted input/change consumer and retains the prior visible value on a blocked or rejected event.
