# 渲染器解譯器命令驗證

隱藏渲染器驗證會先核對實際 Python 執行檔、可選虛擬環境啟動器，以及所屬 Node 程序，先至接納瀏覽器連線。執行檔路徑、建立時間次序、隔離環境設定、檔案雜湊同已持有嘅程序控制代碼，全部仍然要逐項符合。

支援嘅 CPython 轉向器有兩種完整原生命令格式：保留原啟動命令，或者用固定加引號嘅基礎解譯器路徑，加返原有參數。預設設定只會由已核實解譯器路徑同實際驗證參數產生兩個完整字串。唔會用部分比對、參數正規化、其他引號形式或者單憑執行檔相同就放行。中間啟動器仍然必須完全符合原啟動命令。

選中格式會記錄喺用戶端綁定嘅 `interpreterCommandForm`。後續按呢個綁定驗證時，唔接受格式轉換。完整命令會保留喺父子程序證據，並喺受保護操作之後重新觀察。原有注入設定如果只提供 `baseCommand`，仍然只接受嗰一個完整命令。

<a id="verification-and-limitations"></a>

## 驗證及限制

針對性恢復測試共有 17 項通過。新增預設設定回歸涵蓋控制台及 GUI 解譯器名稱、帶空格路徑、直接及中間啟動器父子關係、兩種支援命令格式，以及拒絕改變解譯器、腳本、意圖路徑、額外參數、引號邊界、中間命令或已綁定格式。刻意將轉向候選還原成原啟動命令後，兩個新增解譯器情況都會失敗；恢復實作後再通過。

原先觸發調查嘅來源渲染器執行，喺觀察器綁定同已安裝工具階段之前已停止，冇產生目標啟動收據。原有日誌保留作拒絕接納嘅證據，唔代表瀏覽器或封裝程式驗收。單元測試通過唔等於渲染器互動、原生擁有權生命週期或封裝驗收通過，仍然需要獨立審閱同綁定來源嘅實際執行。
