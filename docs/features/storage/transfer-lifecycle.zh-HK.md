# 受管傳輸及安全磁碟生命週期

原生輔助程序以附加方式提供非同步傳輸控制。舊呼叫者仍可使用現有同步方法。

## 協定

- `startImport` 接受 `paths`，即一至 1000 個位於保管庫資料夾外的絕對來源路徑，立即回傳 `operationId`。
- `operations` 最多回傳 128 筆保留操作記錄，各含 `operationId`、`state`、`bytesCompleted`、`totalBytes`、`completedFiles`、`totalFiles`，以及適用時的安全 `error`。
- `cancelOperation` 接受 `operationId`。取消獨立於控制器及加密鎖。`accepted: false` 表示操作已終止。完成檔案保留安裝，未完成暫存檔丟棄。
- `forceLock` 回傳 `locked`、`busy`、`code`、`activeOperations` 及 `queuedOperations`。執行中或排隊命令、傳輸、準備、同步或檔案系統 I/O 會回傳忙碌。閒置開啟控制代碼不阻止強制鎖定。分派器卸離前阻止新接納，只有引擎釋放並清除自有金鑰後才回傳成功。
- `listFiles` 接受數值 `cursor`、`limit`（1 至 1000）及選用 `revision`，回傳 `items`、`nextCursor`、`revision` 及 `resetRequired`。revision 改變時從零重新分頁。

命令共用一個有界消費者。命令執行期間仍持續讀取控制訊息。已接納要求中繼資料的位元組上限低於 64 MiB；受管檔案內容不排隊，只用一個 64 KiB 明文緩衝區。傳輸要求最多 64 個未完成操作。終止記錄會從有界保留歷史移除。

## 儲存及耐久性

新保管庫使用格式 3。獨立驗證內容區塊最多 64 KiB，並打包到符合設定實體上限的不可變密文 parts。驗證將區塊綁定至 part 識別碼及偏移。現有格式 1、2 仍可讀取。修改大型舊記錄時寫入有界覆蓋層，不重新打包全檔。截斷記錄基礎資料上限，避免之後增長暴露已截斷位元組。

受管匯入建立密文及加密暫存日誌，不會把未完成檔案加入有效命名空間。最終安裝在引擎鎖內進行，不覆寫衝突目的地。安裝前取消移除暫存中繼資料，批次已完成檔案保留。與安裝後競態的取消不能把完成結果改成取消。丟棄暫存留下的不可變密文沒有明文，也不會成為可見檔案。

檔案系統回呼持久儲存本機加密狀態。儲存發佈由同步執行，位於檔案系統回呼鎖之外。revision 未改變時，狀態重用檔案及歷史計數。

## 驗證及限制

`native/MaterialFileEncryptor.Lifecycle.Tests` 以可拋棄合成保管庫測試排隊接納、取消、強制鎖定忙碌結果、原子受管匯入、延後取消語意及 revision 分頁。正式根建置使用 `build.bat /s`。Windows Explorer 互動及安裝程式行為需另作執行驗證；原生協定檢查不證明這些結果。

父程序正常 EOF 會等候已接納要求，受管傳輸仍執行時拒絕釋放引擎。一般鎖定仍拒絕開啟磁碟控制代碼。強制鎖定是另一操作，加密工作仍執行時絕不報告成功。

## 增量日誌及活動

已接受檔案系統變更會附加帶序號加密記錄到本機日誌。每筆驗證長度、序號及前一筆摘要，耐久沖寫後才確認。定期同步把記錄壓縮到檢查點及不可變發佈提交；耐久檢查點先記錄最高處理位置，再淘汰舊日誌。啟動只忽略未完整的末筆記錄，完整記錄驗證或鏈結失敗會被拒絕。`journal` 狀態分開報告附加位元組及 frame、檢查點位元組及數目。`journal.pendingFrames` 與 `sync.pendingLocalFrames` 表示已接納但等待檢查點／發佈的本機變更。

狀態要求由輸入迴圈直接回傳不可變快取快照。快照更新在讀取器之外，因此大型加密操作不能阻止讀取之後的取消要求。無效要求亦不能強迫阻塞狀態更新。

輔助程序記錄加密匯入、編輯、重新命名、還原、取消、匯出及同步活動。同步 worker 明確發佈活動，建立事件不重掃既有清單。`listActivity`、`previewVersion`、`listVersionLabels`、`labelVersion` 及 `exportVersion` 提供所選檔案歷史流程。`startExport` 透過操作登錄加入可取消匯出，同步方法仍相容。使用者選擇的匯出目的地位於儲存及快取資料夾之外。若安裝前準備、解密或取消失敗，原子目的地取代會保留原匯出檔案。

隨機不可變 part 識別碼允許一個 part 含多個獨立驗證區塊。完整性來自每個區塊的驗證及綁定 part 識別碼／偏移，不是把檔名當摘要。回歸檢查拒絕位元組竄改、同大小區塊替換及截斷，亦獨立讀取自行構造的格式 2 密文測試資料。

## 目前檔案匯出原始碼新增

原始碼 `6086ff30c532c6a59a2ddc0869a28651e9a20dc1` 為 `startExport` 加入目前檔案匯出：提供 `path` 或 `versionId` 其中一個，以及 `destination`。目前 `path` 從不可變讀取快照匯出，其參照密文在釋放前受保護，不被快取移除。worker 每區塊最多串流 65,536 明文位元組到同目錄暫存檔，在準備與寫入之間檢查取消，耐久沖寫後原子取代目的地。

安裝前取消保留原目的地並移除暫存輸出。安裝勝過延後取消時報告完成。最終處理清除明文緩衝區並釋放快照。匯出目前檔案不會製造歷史版本。

本段只記錄已實作原始碼行為。在已審閱父基線 `8ec5ef37e593fe4ef8ba88e9e4205bc67c4c36c3`，新增匯出尚未整合。一般掛載記錄早於此變更，不證明它。最終父整合、封裝執行及掛載目前檔案匯出驗收仍未驗證。

## 舊格式驗證記憶體及成本

Windows 上的舊格式 1、2 記錄使用 Microsoft CNG `BCryptDecrypt` 驗證鏈結 API。第一輪驗證全記錄到會清除的有界丟棄緩衝區。只有最終標籤成功後，第二輪才透過同一個排除寫入的檔案控制代碼解密所需範圍。格式 1 保留記錄偏移關聯資料；格式 2 同時保留關聯資料及全物件 SHA-256 身分。不建立明文暫存檔。

舊記錄全記錄共用一個驗證標籤，小範圍讀寫仍需與舊記錄長度成比例的驗證工作，解密亦可能掃描所需範圍之前的內容。有界覆蓋層避免重寫全舊檔，卻不令舊驗證變成可獨立定位。現代格式 3 保留每區塊最多 64 KiB 的獨立驗證。

自有傳輸緩衝區共用程序級 64 MiB 接納預算，涵蓋目前讀寫、暫存匯入、受管匯入／匯出、同步、密文複製及舊格式驗證。保留額保守計入操作所用有界串流緩衝區。耗盡時產生可重試失敗，不會持有引擎鎖等待。這是傳輸緩衝區上限，不是程序工作集上限；呼叫者輸出、中繼資料／物件圖、執行環境開銷及作業系統密碼學供應者內部配置另計。`transferBuffers` 顯示執行中／峰值保留位元組及上限；`VaultEngine.LegacyReadBuffers` 另報舊讀取器已計算工作區。

針對性測試包括獨立 90,000,000-byte 格式 1、2 記錄、單位元組覆蓋修改、區塊邊界及空記錄、無效關聯資料／標籤／密文／截斷、共用預算耗盡、並行讀取及兩輪期間取消。供應者契約見 [Microsoft 驗證密碼模式資訊參考](https://learn.microsoft.com/en-us/windows/win32/api/bcrypt/ns-bcrypt-bcrypt_authenticated_cipher_mode_info)。

## 背景排程偏好

輔助程序預設 `responsive` 效能模式。Windows 上同步受管匯入暫存、匯出、計時維護及同步採低於一般的執行緒優先權。每個範圍在 `finally` 還原呼叫執行緒原優先權；非同步讀取在匯入範圍之外。程序優先權、控制讀取器及前景檔案系統回呼不變。

`setPerformanceMode` 接受 `{ "mode": "responsive" }` 或 `{ "mode": "throughput" }`。Throughput 模式不改既有執行緒優先權。`status` 及 `statusSummary` 報告 `performanceMode`。設定在傳輸回應能力下提供選擇、本機儲存，並在啟動輔助程序時重套。排程優先權只是回應能力提示，不保證吞吐量或延遲。

受管匯入失敗可在已遮蔽 `errorCode` 旁提供選用 `errorPhase`，固定值為 `metadata`、`source-open`、`source-read`、`staging-begin`、`staging-write`、`install`、`activity`。不包含例外文字、路徑或堆疊。安裝後記錄活動失敗仍保留完成檔案及其完成計數。階段識別當時操作，包括退棧期間釋放，不宣稱底層作業系統原因。

選用生命週期測試模式 `--large-import-only`、`--large-managed-only` 及 `--large-background-only` 使用 10 MiB part 上限測試合成 512 MiB 匯入，區分核心暫存、受管來源讀取及定期控制器工作，不代替封裝掛載磁碟執行。

可信儲存例外的操作診斷另含 `storageStage`：`part-create`、`part-write`、`part-flush`、`part-finish-rename`、`part-cleanup`、`metadata-temp-create`、`metadata-write`、`metadata-flush`、`metadata-replace` 或 `metadata-cleanup`。固定值識別儲存動作，不暴露路徑或作業系統訊息。原子中繼資料寫入失敗後，若清理也失敗，會保留原寫入例外，現有目的地保持不變。

原子中繼資料取代只重試已確認 Windows 共用衝突。Sharing／lock violations 直接符合；access denied 只有在獨立 delete-access 探測於舊或新檔回報 sharing／lock violation 才符合。唯讀屬性及永久存取拒絕不符合。取代保留同一已耐久沖寫暫存檔，最多等候十次、每次 15 ms。耗盡後保留第一個例外及原目的地。目前區塊收尾時，控制讀取器保持獨立。
