# 加密 Git 歷史及私人儲存庫傳輸

`GitVaultHistory` 使用內附或已安裝的 `git` CLI 建立真正提交、樹及二進位 blob 物件。工作目錄及可變 `.git` 目錄必須在本機且位於保管庫來源資料夾之外。只接受 `vault.json`、`parts/<opaque-id>.mfe` 及 `commits/<opaque-id>.mfe`，識別碼為 32 或 64 字元十六進位。提交訊息或樹名稱不寫入原始檔名、檔案路徑、憑證或未加密快照中繼資料。提交使用通用儲存身分及訊息。密文檔案及密碼學保管庫標頭不可變，位元組衝突會令操作失敗。

加密子項目及其快照中繼資料發佈後，呼叫 `RecordSnapshotAsync(paths)`。提供明確來源相對檔案，不要枚舉所有歷史內容。每個提供的檔案必須已存在本機。部分用戶端應包括已有的新分塊及中繼資料，不包括缺失的歷史分塊。沒有變更不會建立空提交。`ListSnapshotsAsync` 不讀取內容物件即可列出提交識別碼。`ReadEncryptedFileAsync(commit, path)` 取得加密歷史檔案，可按需要取回該單一承諾 blob。

`FolderVaultTransport` 保留一般資料夾供應者。它驗證要求路徑及可用性；不可變子項目優先發佈仍由現有引擎負責。它不會將可變 Git 狀態複製到同步來源資料夾。

`PrivateGitHubVaultTransport` 逐保管庫以嚴格 `owner/repository` 識別碼選擇，需要現有私人 GitHub 儲存庫及 GitHub CLI 認證。複製前及每次同步／發佈前，均透過 `gh repo view` 檢查私隱。設定的 origin 必須符合所選儲存庫。Git 忽略系統及全域設定，將憑證輔助程式重設為可信 GitHub CLI `auth git-credential`，並停用互動提示。有效 fetch 及 push 目的地各自必須只指向所選私人儲存庫；push URL 及本機 URL 重寫不能改道發佈。傳輸例外不包含工具輸出，避免洩漏憑證或本機路徑。

私人供應者需要專用空白本機歷史目錄，與一般本機歷史目錄分開。它使用 `--filter=blob:none --no-checkout` 複製，不進行工作樹 checkout，並明確具體化加密提交中繼資料及根保管庫標頭；必須有 `blob:none` promisor 設定。現有完整複製會被拒絕，不會稱為延遲載入。伺服器不支援篩選時會明確拒絕。擷取及列出樹不要求歷史 part blobs。`EnsureFileAsync("parts/<id>.mfe")` 使用 `git show` 取得所選加密物件，再以原子方式發佈到來源資料夾。中繼資料同步只具體化加密提交檔案。

同步擷取目前 main 分支、驗證樹路徑、建立已驗證的不可變樹聯集及真正 Git 合併提交。並行不可變快照新增會產生有雙親的真正合併提交，絕不強制推送。不可變物件或保管庫標頭衝突會停止協調。若另一寫入者在 fetch 與 push 之間勝出，正常 push 會被拒絕；檢查保管庫狀態後再同步。Git 認證、網絡、合併及發佈失敗會明確報告，不會稱為成功離線同步。空儲存庫保持空白，直至記錄真正快照。

引擎整合把加密檔案取回委派連接到 `EnsureFileAsync`，在 `HistoryChanged` 後記錄新發佈且可用的快照檔案，並在重播新收到的加密中繼資料前同步傳輸。控制器負責後端選擇及本機路徑；兩個後端都不需要明文檔名或加密金鑰。歷史目錄不可置於同步資料夾或跨保管庫重用。

## 驗證

執行 `dotnet run --project native/MaterialFileEncryptor.Transport.Tests`。獨立執行檔使用真正暫存 Git 儲存庫及支援篩選的本機 Git 伺服器，涵蓋二進位 blob 來回、舊快照讀取、無變更快照、無效路徑、不可變衝突、儲存重疊拒絕、Git 存取前私隱拒絕、通用提交訊息、中繼資料同步後缺失承諾 blob、按需取回、並行快照協調及雙親合併。測試注入 GitHub CLI 私隱回應。實際 GitHub 認證及網絡服務可用性需另作操作驗證。

## 程序及轉換隔離

`VaultProcessRunner` 接受明確可信執行檔路徑；否則先檢查原生執行檔目錄旁的 `../tools`、開發用 `resources/tools` 及直接 `tools` 目錄，才使用 PATH。內附布局為 `git/cmd/git.exe` 及 `gh/bin/gh.exe`。工具缺失會產生清楚的可用性錯誤。每個程序有連結的 60 秒逾時，取消會終止其程序樹。此元件不下載工具。

記錄會拒絕不相關的已暫存路徑，但不丟棄它們。完整結果樹經驗證，只含一般密文檔案。`hash-object --no-filters`、`update-index --cacheinfo`、`write-tree` 及 `commit-tree` 避開 clean/smudge filters、attributes 及自訂合併驅動。同步亦使用樹底層操作而非 checkout 或工作樹合併，即使本機 attributes 有敵意，密文仍保持位元組一致。所屬控制器須序列化記錄、同步及取回呼叫。

`ContainsFile(path)` 從最近已驗證樹名稱清單回答，從不要求 blob。空私人目的地同步時不會虛構提交或發佈另一分支。測試亦涵蓋已暫存明文保留、敵意 clean filters、attributes 下精確位元組、改道 push URL、有效 push 重寫及空目的地。

## 選用實際私人供應者驗證

明確建立並驗證專用私人合成測試儲存庫後，可執行 `dotnet run --project native/MaterialFileEncryptor.Transport.Tests -- --live-private OWNER/REPOSITORY`。此選用模式只發佈產生的 AES-GCM 密文、使用既有可信 GitHub CLI 認證途徑、對真正供應者檢查延遲取回及並行協調，並證明結果 main ref。它保留測試儲存庫及本機暫存資料供審閱。不可指向正式保管庫。中斷的檢查只可重用先前已驗證且屬該工作的合成測試資料。測試身分及本機操作路徑應放私人交接，不放公開文件。

一次針對專用私人合成 GitHub 儲存庫的有界實際驗證通過十項檢查：初始化、加密發佈、只複製中繼資料、缺失承諾內容物件、樹可用性、位元組一致取回、並行協調、雙親歷史、舊快照取回及最終 main ref 一致。這只證明受測 GitHub 路徑及既有認證帳戶，不證明其他供應者、任意儲存庫設定、傳輸上限或新機設定。測試詳情私人保留。

## 有界發佈

每次 push 預設新 Git 物件未壓縮位元組預算為 1 GiB，低於儲存庫傳輸上限。記錄將加密內容分成有界中間提交，之後才發佈快照中繼資料。同步從已發佈 ref 規劃增量快進發佈，計算每步新提交、樹及 blob 的精確大小，並在任何傳送前驗證整個計劃。每次 push 再驗證私隱及有效目的地。並行 push 被拒絕會停止餘下計劃並保留本機歷史。

現有提交或合併的新物件閉包超過預算時，在超大 push 前明確失敗。不會改寫、事後分割、強制推送或盲目重試。保留本機歷史及密文，透過審閱過的復原途徑建立較小內容批次。選用建構器預算支援小型決定性測試，最少 8 KiB、最多 1 GiB。本機測試證明內容先於中繼資料發佈、每個計劃 push 低於注入的 16 KiB 預算，以及超大現有提交會保留而不 push。

## 離線快取初始化

私人供應者成功驗證後，會在獨立 `.git` 目錄內本機收據記錄所選儲存庫身分。匹配的既有收據允許 `InitializeAsync` 只作本機目的地、部分複製設定及樹驗證。`IsCachedInitialization` 報告此途徑，不代表網絡已連接或未快取內容可用。新複製或沒有匹配收據的既有歷史仍需線上私隱驗證。`SyncAsync` 永遠執行線上私隱、擷取及發佈檢查，明確報告連線失敗。控制器可在連線失敗後解鎖已快取加密資料，同時顯示連線狀態，並拒絕不可用內容讀取。
