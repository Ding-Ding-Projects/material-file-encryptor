# 瀏覽器下載交接

配套擴充功能提供由用戶明確選擇嘅連結右鍵選單指令。「配對瀏覽器」會要求喺已解鎖桌面批准。原生接收器要求精確已註冊擴充功能來源、原生同意，同埋十五分鐘後到期嘅不可預測工作階段。桌面上鎖或接收器關閉就會撤銷配對。每個工作階段最多接收六十四個唔重複建議，同時最多兩個要求。工作階段只留喺擴充功能記憶體，唔會持久儲存或記錄。

建議包含 HTTPS 網址、冇路徑嘅建議檔案名稱，同埋非負瀏覽器識別碼。未知欄位、不安全網址協定、內嵌憑證、不安全連接埠、路徑字元同重複建議都會拒絕。原生訊息使用 Chrome 四位元組小端序長度前綴、嚴格 UTF-8 JSON，同埋 64 KiB 限制。擴充功能冇下載或網頁存取權限，唔會攔截或取消現有瀏覽器傳輸。

收到建議之後，桌面會發出開始下載狀態，列明來源同建議名称。`prepareCapturedDownload` 開啟原生目的地選擇器，再建立準備好嘅佇列項目。現有 `startDownload` 操作係另一個明確確認；取消會保持傳輸未開始。真正傳輸保留現有公共 DNS 驗證、重新導向檢查、大小限制、進度、取消，同埋原子方式建立新目的地檔案嘅行為。

## 整合邊界

`browser-extension/` 係配套來源，唔係已安裝或已簽署擴充功能套件。最終擴充功能身份必須由專案擁有嘅套件金鑰導出，再註冊至真正原生主機資訊清單。已安裝主機必須喺連接 `createBrowserDownloadReceiver` 之前，驗證作業系統提供嘅呼叫來源。服務嘅 `receiveBrowserProposal` 入口只供主機使用，唔係呈現層或普通瀏覽器要求操作。主機執行檔封裝、用戶可見安裝、簽署證明同註冊都係獨立工作；開發測試唔會改動瀏覽器設定檔或登錄。

桌面必須顯示獨立而保持最上層嘅開始同完成表面，另有下載中表面。要由已安裝擴充功能開始，實際操作同擷取整個流程，先可以聲稱已驗證呢三個狀態。來源測試同注入訊息唔能夠證明已安裝瀏覽器交接或顯示狀態。

## 安裝時配對設定

已安裝嘅應用程式會喺 `--squirrel-install` 同 `--squirrel-updated` 為目前用戶登記原生主機，並喺 `--squirrel-uninstall` 移除該登記。配套擴充功能係由應用程式資源入面嘅 `browser-extension` 資料夾以未封裝方式載入。佢嘅資訊清單 `key` 將擴充功能 ID 固定為 `hfabajdjnmccemhokjnipmaabdpljbbg`，呢個係主機唯一接受嘅來源。詳情見原生主機文章。已安裝嘅配對仍然未端到端試過。

## 驗證

`test/browser-download-receiver.test.js` 驗證原生批准、工作階段撤銷、呼叫者白名單、嚴格建議形狀、網址同路徑檢查、重播限制、同意期間上鎖，同埋有界限嘅分段訊息解碼。現有下載服務測試會另外驗證實際佇列嘅網絡同目的地保護。

## 本機擴充套件封裝與傳輸識別

擴充套件封裝入口透過 `scripts/build-browser-extension.mjs` 準備本機 `vendor/material.js`、`vendor/search.js` 同 `vendor/regex-worker.js`。Material Web 2.5.0 同 esbuild 0.25.11 維持固定版本。準備收據記錄來源及輸出雜湊，明確標示簽署、安裝同執行驗證尚未進行。彈出頁程式唔使用 CDN。

原生準備會發出帶有 `browserCaptureId` 嘅就緒下載；傳輸事件保留呢個識別碼直到完成或失敗。取消待處理提案會發出 `browser-proposal-cancelled`。配套保留提案識別碼，透過 `{type:'status',session,id}` 查詢原生接收器。提案回覆代表等待確認，唔代表傳輸完成。已安裝呼叫者及三個畫面嘅實際證據仍待完成。
