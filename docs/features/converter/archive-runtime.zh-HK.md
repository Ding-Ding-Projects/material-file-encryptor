# 讀取 7z 同 RAR

封存轉換器使用 `archive-runtime-manifest.json` 記錄嘅精確 7-Zip 26.04 發佈者二進位檔，提供 7z 同 RAR 清單及解壓流程。唔支援建立 RAR。發佈者嘅[下載頁](https://www.7-zip.org/download.html)連到[官方版本](https://github.com/ip7z/7zip/releases/tag/26.04)，其 API 提供固定資產摘要。

## 封裝

由建置入口執行 `node scripts/converter-archive-runtime.mjs <new-output-directory>`。程式會驗證發佈者套件同對應來源封存檔，先只抽取 `7z.exe`、`7z.dll` 同 `License.txt`。結果目錄亦包含完整未改動嘅 `7z2604-src.tar.xz`。有效現有輸出會重用；無效現有輸出會保留並拒絕。新內容喺同層暫存目錄驗證，再重新命名到尚未存在嘅目的地。

將回傳嘅 `sevenZipPath`、`sevenZipSha256`、`sevenZipDllPath` 同 `sevenZipDllSha256` 作為 `archiveRuntime` 傳入 `createWindowsSandboxProvider`。四個檔案都要封裝。每個階段之前重新計算執行檔同 DLL 雜湊。啟動會對細型 7z 同 RAR 測試檔執行真實隔離清單操作。缺少呢啲證據，封存項目保持停用。呢個執行環境唔會搜尋 PATH，亦唔會執行下載嘅安裝程式碼。

發佈者執行檔冇 Authenticode 簽署。信任依據係官方 HTTPS 發佈者連結、SHA-256 版本資產摘要，同個別抽取檔案雜湊。呢個唔代表可重現二進位建置，亦唔代表編譯器已獨立驗證。分發執行環境時要保留完整來源封存檔同 License.txt。授權包含 LGPL、BSD 聲明同 unRAR 限制；RAR 解碼器唔代表有權重建專有 RAR 編碼器。

## 安全同支援子集

每次工具呼叫直接喺已驗證 AppContainer 同單程序 job 執行，冇網絡能力，記憶體限制 256 MiB，原生期限 30 秒。完整清單／解壓流程亦有合計 30 秒期限同取消傳遞。原生啟動器只接受固定 7z／RAR 清單或標準輸出解壓命令，唔接受任意命令參數。

轉換器限制來源 64 MiB、清單 1 MiB 同 1,000 項、解壓 128 個檔案、每個檔案 16 MiB、總展開位元組 64 MiB，同展開比例 100:1。名稱會經現有路徑穿越、絕對路徑、裝置名稱、深度同大小寫衝突檢查。密碼、多部分項目、連結、串流同 Unix 特殊檔案中繼資料會被拒絕。解壓對每個已驗證名稱停用萬用字元匹配，只寫入標準輸出，所以封存路徑唔會變成工具控制嘅檔案系統目的地。輸出交畀佇列之前，會檢查精確長度同任何提供嘅 CRC。解碼器結束狀態必須表示成功。空目錄、權限同封存中繼資料唔會還原。

呢個子集刻意拒絕包含底線嘅名稱。固定來源中，`CPP/Common/StdOutStream.cpp` 會將重新導向清單名稱嘅 CR／LF 改成底線。拒絕呢個字元，避免將正規化拼法當成精確成員名稱。呢個係明確互通限制，唔代表支援全部有效封存檔。

現有佇列驗證完整輸出集合，要求目的地目錄授權，保留來源同現有目的地檔案，並喺發佈之前暫存輸出位元組。任何解壓輸出都唔會執行。測試涵蓋儲存式 7z 同 RAR 測試檔、官方壓縮 7z 內容、路徑穿越同損壞內容拒絕、取消，同輔助程式竄改。
