# Local tools workspace design

The converter uses four task stages: source selection, categorized formats, options and queue history. Selection advances to the next relevant stage while every stage remains reachable through the keyboard tab strip. Format categories retain independent bounded expression searches and unavailable adapters remain visible with their reason.

Local models uses a five-panel workspace. Runtime maintenance is grouped in a disclosure, leaving model discovery first. Registered Material fields, selectors, file pickers and buttons provide the shared control contract. Model selection stays visible through its pressed state and a detail surface. The pull cart has per-item progress. Local chat retains private attachments and the redacted export route.

Server preparation remains preparation only. Version selection is a contained list and verified distributions appear in separate operation surfaces. No execution target, license acceptance or startup capability is added.

## Evidence boundary

This document describes implemented source, not built visual verification. Integrated-build captures, minimum-view and scale checks belong to the integration acceptance pass. No existing capture is relabelled as proof of this redesign.
