# 外部指引時效檢查

`scripts/check-vocabulary.mjs` 檢查明確設定嘅外部指引來源係咪仍然有效，唔會將內容或者摘要複製入本儲存庫。檢查唯讀，亦唔能夠證明有人或者代理已閱讀或實行指引。

## 設定

將程序環境變數 `PRIVATE_INSTRUCTIONS_SOURCE` 設為儲存庫外現存檔案嘅絕對路徑。亦可以設定儲存庫本機 `privateInstructions.source` Git 設定值；建置同 hook 只會喺環境變數缺席時讀取佢。檢查器唔會搜尋個人目錄或者猜測來源位置。兩個設定都冇嘅時候，會輸出通用略過訊息並成功結束，讓冇私人指引嘅參與者繼續建置。明確空白環境變數或者無效設定會失敗。

外部來源必須有而且只有一個名為 `Vocabulary and locations` 嘅二級標題。字典範圍由該標題開始，到下一個一級或二級標題之前，或者檔案結尾為止。標題以行首正則表達式識別。CRLF 同 CR 會正規化成 LF，範圍最後保留一個 LF，再計算 SHA-256。其他章節唔影響摘要。

附屬檔案名稱係已設定來源檔名後加 `.lock.json`。嚴格結構只有兩個欄位：數字 `version` 必須係 `1`，`sha256` 必須係小寫 64 字元範圍摘要。來源同附屬檔都應放喺公開儲存庫外。擁有人只可以喺審閱正式來源後建立或更新附屬檔；建置同推送唔會自動產生、修理或者更新佢。

來源缺失、附屬檔缺失或格式錯誤、過期摘要、重複或缺失標題、無效 UTF-8 同輸入過大，都會以結束碼 1 失敗。來源文字最多 2 MiB，附屬檔最多 4 KiB。輸出唔包含來源路徑、指引文字、摘要、數量或者底層例外細節。

## Hook 同建置整合

已納入版本控制嘅 `.githooks/pre-push` 呼叫同一個檢查器，並傳回其結束狀態。啟用 hooks 目錄仍然係儲存庫擁有人嘅明確操作，唔好覆寫現有 hook 設定。Hook 需要 PATH 入面有 Node.js，唔會安裝工具。根建置入口喺工具啟動之後、輸出暫存之前呼叫檢查器。本機 hook 同私人來源設定唔屬於分發來源內容。

執行 `node --test test/check-vocabulary.test.js`，會用中性合成測試資料覆蓋缺席、有效鎖、過期同格式錯誤鎖、換行、範圍擷取、外部路徑限制，同唔披露內容嘅輸出。測試資料唔包含正式私人內容。
