# 特權存取主機整合

特權主機核實密碼、PIN 同 TOTP，保存錯誤嘗試嘅等待期限，評分一次性等待挑戰，並限制每滾動一小時最多三次成功跳過等待。答啱挑戰只會結束等待，唔會登入設定檔、解鎖元素或開放歷史存取。

## 正式工廠同可信身分

每個受保護主畫面生命週期建立一個配接器：

```js
const journal = createAccessMutationHistory({dataDirectory, toolsDirectory});
const access = createAccessIntegration({
  dataDirectory,
  toolsDirectory,
  credentials,
  getMainFrame,
  recordMutation: event => journal.record(event)
});
```

配接器提供 `request(senderFrame, action, payload)`、`supports(action)` 同 `close()`。可信主程序處理器先驗證請求來源，再建立 `{senderFrame: event.senderFrame}` 作為功能服務上下文。`getMainFrame` 傳回主程序目前持有嘅畫面物件。配接器要求物件參照一致，自行衍生操作者識別碼，並保留喺非同步請求上下文；非同步工作之後亦會再核對身分。畫面請求內容唔可以指定操作者或畫面。

Loopback 或其他冇已核實畫面嘅呼叫者冇操作者身分，請求會被拒絕。唔可以借用目前畫面令不可信請求通過。結束生命週期時關閉配接器同記錄器，撤銷權限並中止佢哋擁有嘅 Git 程序。

## 權威模式同執行檔

學校模式來自原生應用程式資料目錄嘅 `shared-settings.json`。初始設定不存在代表停用；格式錯誤、超出大小限制或符號連結會令操作停止。畫面端唔可以覆蓋呢個值或等待期限。

主機使用 `createForgeToolResolver(toolsDirectory)` 同可信安裝包嘅 `forge-executables.json`。每次執行都核實隨附執行檔嘅路徑及實際摘要，再檢查 `git version 2.56.0.windows.2`。唔會從 PATH 揀 Git，亦唔接受畫面端提供摘要。工具遺失或改變會停止記錄。封裝執行檔驗證與合成測試執行器係兩項獨立證據。

## 請求同受保護儲存合約

配接器處理 `ACCESS_HOST_ACTIONS` 入面所有動作，以及 `credentialGet`、`credentialSet`、`credentialDelete` 同 `credentialList`。現有資料夾動作仍由原處理器負責。外層橋接驗證須保留；配接器另外執行 `validateAccessHostRequest` 或精確憑證結構驗證，並喺排隊前固定已驗證請求內容。

儲存提供 `get`、`set`、`delete`、`list`、`readVersioned(key)` 同 `compareAndSetVersioned(key, expectedRevision, replacement)`。版本讀取傳回值同版本憑據；條件寫入喺同一條儲存序列內比較並寫入，再傳回更新狀態同新憑據。每次成功寫入都會改變受保護持久憑據，包括相同值寫入同刪除。刪除後仍保留版本墓碑；null 替代值代表刪除。單靠值比較唔足以防止還原覆蓋後來寫回相同值嘅另一個操作。

保留嘅 `lock:` 同 `profile:` 主機記錄唔會經畫面憑證 API 開放。畫面端唔可以讀取或取代歷史金鑰、待完成意圖、嘗試計數或操作者權限。

## 憑證寫入准入

驗證器同顯示名稱修改需要獨立認證嘅加密歷史服務。初次建立設定檔同元素鎖唔需要歷史密碼，但會使用只限新建嘅版本寫入，並等候遮蔽一般歷史記錄完成後先回報成功。

新建唔可以覆蓋現有憑證。目前介面會先認證及移除現有鎖，再建立替代鎖，唔會暗中新增憑證重設端點。移除需要近期成功驗證，並綁定操作者、目標同未改變嘅記錄版本；另一個容許情況係同一操作者取消自己新建項目，且建立憑據仍有效。新畫面唔可以重用另一畫面嘅建立憑據。

舊有 `history:*` 讀寫需要已驗證設定檔。`waitCancel` 會撤銷對應目標權限。歷史操作喺非同步讀取期間保留同一權限身分、世代同到期時間，交出資料前再檢查。若取消發生喺已儲存寫入期間，只會還原該次寫入自己嘅版本；其他操作後來寫入嘅內容會保留，並回報復原需要。

一般歷史回呼只接收 `{version, action, target, at}`。缺少記錄能力時，設定檔或元素修改會喺寫入前停止。記錄失敗會還原自己擁有嘅憑證版本，並嘗試新增遮蔽還原記錄；持久記錄失敗時絕不回報修改成功。

## 畫面整合

經正式功能橋接提供 `services.accessHost(action, payload)`。個人化設定嘅 `services.recordDisplayName(value)` 使用 `displayNameSet`；首次掛載設定前讀取 `displayNameRead`；獲授權還原嘅名稱透過 `onDisplayNameRestore` 套用。還原唔應額外產生另一筆修改。其他改名途徑，包括重設偏好設定，都要使用相同已授權記錄流程。

只有提供主機配接器先會出現歷史分頁。分頁有獨立密碼、明確設定／解鎖／鎖定控制、完整搜尋、日期及動作篩選、標籤、比較、遮蔽匯出，以及經確認嘅還原／保留期／清理操作。設定檔登入唔會暗中打開歷史。

## 加密歷史同擁有權

加密歷史權限有效十分鐘，並綁定可信操作者。AES-256-GCM 快照包含驗證器記錄同顯示名稱。應用程式本機資料目錄嘅 Git 只接收密文同非敏感動作名稱，金鑰同尾端摘要留喺作業系統受保護儲存。

修改按次序進行，並使用持久版本憑據。記錄失敗只會還原仍屬於該操作嘅值；還原本身會新增項目，唔會改寫較早提交。後來寫入嘅相同值仍屬另一個版本，唔可以覆蓋。

清理只會喺管理器隱藏過期項目，歷史加密提交仍然保留，所以唔係安全抹除或磁碟空間回收。目前忘記歷史密碼冇復原或重設途徑。實作亦唔宣稱憑證儲存同 Git 之間係同一個原子交易。

## 加密記錄中斷復原

加密封套先寫入專用暫存目錄並同步，再保存受保護待完成意圖。意圖綁定暫存及最終相對位置、精確密文摘要同原本受保護尾端。

中斷後，主機只可以用受認證暫存或最終字節完成遺漏提交。更新受保護尾端前，會核對已提交內容同目前檔案。因此尾端寫入失敗可以復原已提交記錄，並喺自己版本還原後新增補償記錄。未知內容、符號連結、擁有權改變或受認證字節遺失，都會停止復原，唔會刪除或取代。未被引用嘅暫存檔仍會保留。

## 遮蔽初始記錄同管理器發現方式

初始記錄器只保存版本、固定動作、穩定目標同 UTC 時間。憑證值、因素、操作者同任意內容都會被拒絕。唔需要設定檔或加密歷史密碼，初次設定因此可以記錄生命週期。

操作按次序進行：同步不可變待完成資料檔、用經核實隨附 Git 提交指定最終記錄、核對已提交字節，最後先回報成功。檔名綁定內容摘要以偵測改變。之後嘅呼叫或新程序會先復原待完成記錄，再接受新工作。未知待完成檔案或字節不符會停止復原並原樣保留。

記錄存放喺本機應用程式資料目錄嘅 `access-mutations/records`，與加密快照分開。主機專用 `list({limit})` 最多按時間排序傳回一千筆記錄。已認證管理器可經所屬主機發現並合併呢個清單。記錄器冇新增無限制畫面端點或憑證識別碼例外；管理器橋接同顯示仍係明確整合工作。呢份記錄只係中繼資料，唔係認證權威，亦唔代替加密快照。

## 驗證同尚待完成嘅邊界

`test/local-access-host.test.js` 覆蓋受保護挑戰、持久額度、獨立歷史權限、加密臨時 Git 記錄、版本擁有權同中斷復原。`test/local-access-integration.test.js` 覆蓋可信畫面准入、保留識別碼、原生設定、執行檔變更、記錄失敗，以及權限讀取、已儲存寫入同交回讀取結果時嘅取消。`test/local-access-mutation-history.test.js` 透過合成解析器及執行器驗證臨時 Git 真實提交，唔代表已執行封裝原生執行檔。

所有測試都使用合成資料，唔會使用真實保管庫或用戶憑證。歷史間歇 Node WebCrypto 不一致仍未解決，除非另有綁定來源嘅執行證據正式結案。封裝瀏覽器比較成功唔等於主程序執行環境合格。正式傳送者接線、已安裝執行檔可用性、管理器發現流程、真實畫面驗收同加密執行環境驗收，都要各自記錄證據。
