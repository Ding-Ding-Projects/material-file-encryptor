# 本機介面工作計時

桌面介面提供唯讀 `window.mfePerformance.snapshot()`，俾受控嘅本機量度使用。紀錄只包含固定階段同畫面識別碼、程序內序號、結果，以及單調時鐘嘅開始時間同耗時。預設保留 128 筆完成紀錄同最多 32 個未完成區段。資料唔會上傳或持久保存。查詢、檔案路徑、文章內容、憑證同原生回應內容都唔會進入紀錄。

首次鎖定磁碟就緒紀錄要求目前狀態仍然鎖定、建立同解鎖操作可用，以及內容已連接並顯示。歷史同回收筒導覽就緒會跟住目前封存請求、篩選列同控制項。文件就緒會等初始文章同篩選導覽完成。成功但空白嘅集合仍然就緒；不可用工作、worker 錯誤、被新請求取代同銷毀都有獨立結果。模組掛載同啟動完成只係階段，唔代表全部工作流程就緒。其他導覽明確標記為未量度。

就緒內容亦會等待實際觀察到嘅靜態樣式表載入、文件字型就緒承諾、目前自訂元素註冊，以及佢哋提供嘅初始更新完成訊號。呢啲唔證明像素正確、無障礙、每個巢狀 shadow 元件或之後操作。觀察同啟動並行，最多等五秒，唔會改排程器或原生操作。關閉頁面會中止觀察，並將未完成計時標記為已銷毀。

比較正常正式封裝時，要用相同隔離測試資料、建置設定、視窗尺寸、縮放、主題、語言、原生功能可用性同操作次序。另行記錄原始碼提交、封裝雜湊同原始快照。使用介面嘅單調時鐘耗時，排除工具連接、輪詢、截圖同驗證開銷。多次冷啟動同重複導覽分開比較。開發或驗證設定屬於另一組。呢項計時功能冇聲稱端到端速度改善，實際封裝執行量度仍然待做。

針對性合成測試涵蓋固定識別碼、有界保留、唯讀快照、過期導覽、銷毀、實際資源完成、逾時同錯誤、成功空白搜尋、正則 worker 錯誤同並行請求結果。呢啲測試唔代替封裝執行驗證。

## 渲染器測試取消同時間記錄

原始碼渲染器案例保留原本嘅 120,000 ms 同 90,000 ms 測試期限。實際測試
context 嘅 `AbortSignal` 會先控制原始 page、locator、keyboard 同 mouse
adapter，再包上 Material 控制包裝器。每次派發前、等待進度持久化之後，
以及已派發操作完成之後，都會檢查准入。因此 Material 欄位完成 evaluation
之後，如果測試已取消，就唔會再接住執行輸入。

進行中嘅操作唔會事後被標記成已取消或者已終止。操作真正完成時可以追加
完成記錄，然後 adapter 傳回原本嘅 abort 原因，阻止下一個斷言或者互動。
呢啲檢查唔會終止原生程序、打斷現有 driver 呼叫，亦唔會聲稱取消同程序
退出發生喺同一時間。

進度喺取得瀏覽器之前初始化，以案例開始時計算單調遞增嘅經過時間。
版本 3 嘅 `progress.json` 新增一次性 `deadline` 快照，包含經過時間、最後
開始同最後完成嘅記錄，以及獨立 phase/request 快照。之後嘅完成記錄同
128 列滾動歷史都唔可以覆蓋呢個快照。舊證據保留原本 schema 同原始碼綁定。

所擁有嘅瀏覽器關閉同獨立 server 關閉，仍然喺已取消嘅 page adapter 之外
執行。測試取消後唔再執行診斷 page evaluation。還原期間會等待已排隊嘅
進度持久化完成。呢個改動改善取消行為同診斷，唔代表執行更快、實際行為
成功、画面擷取通過驗收，或者原生資源已完全清理。

針對性原始碼檢查會用唔執行操作嘅 page endpoint，執行真正 adapter 函數同
兩個真正案例 callback，證明取消後拒絕輸入同 evaluation、進度寫入同
Material evaluation 期間取消、進行中操作完成如實記錄、歷史滾動後期限
快照不變，以及所擁有資源仍然關閉。移除取消檢查，或者容許後續記錄改寫
期限快照，都會令目標檢查失敗。
