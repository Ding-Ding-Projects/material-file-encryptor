# Public documentation workspace role

The public browser workspace opens documentation first. It provides documentation, changelog, preferences, local access, status, and authorized converter and local-model tools. Encrypted-drive file browsing, import, opening, export, offline actions, mounting, synchronization and locking belong in the installed application and are not exposed here.

## Client mediation

The browser adapter accepts only feature requests for its explicit personalization, status, converter and local-model action lists. It rejects primary drive operations and unsupported feature namespaces before reading connection status or sending any network request. The installed application's server API remains unchanged. Pairing still requires loopback, a one-use code and explicit desktop approval. Disconnection clears credentials and the local tool views.

## Confirmation and page lifetime

Output replacement, model deletion and session deletion use the shared in-surface two-key confirmation and full slider. An exact required phrase or model name remains mandatory where the consumer requires it. No operation is approved by merely opening or cancelling the dialog. Owner teardown cancels pending confirmation.

A cached browser navigation clears local pairing and private wording while retaining usable document controls. Normal departure disposes tools, timers, observers and shared controls. Saved legacy Files tabs are removed from open and restore inventories, preserving other saved tab, group and notification state.

## Verification

Focused behavioral tests cover rejection before network access, retained companion mediation, real two-key and slider interaction, exact-text refusal, cancellation, owner abort and legacy-tab migration. Server tests retain installed-context API coverage. Source checks do not establish built browser layout, live pairing, native tool acceptance or deployed behavior; those remain separate verification.
