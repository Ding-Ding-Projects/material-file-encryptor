# 原生加密資料夾儲存

`native/MaterialFileEncryptor.Core` 是 Windows 檔案系統主機使用的 .NET 8 儲存引擎。Explorer 操作直接讀寫加密命名空間。引擎不建立明文工作資料夾。磁碟區解鎖期間，明文存在應用程式或檔案系統驅動緩衝區；已解鎖電腦能讀取掛載檔案。

## 憑證及密碼學

新保管庫產生隨機 32-byte 主金鑰。密碼 UTF-8 位元組，或 32-byte 至 1 MiB 金鑰檔的精確內容，經 PBKDF2-HMAC-SHA-256（隨機 32-byte salt、600,000 次迭代）再以 AES-256-GCM 包裝主金鑰。`VaultCredentials.GenerateKeyFile()` 產生 32 個隨機位元組。憑證由主機負責；核心不儲存密碼或金鑰檔路徑。主機可為明確啟用的 Windows DPAPI 憑證匯出已解鎖主金鑰，並以 `OpenWithMasterKey` 還原。

設定的保管庫識別碼、憑證類型、KDF 參數及已包裝金鑰是公開資料。路徑、長度、時間戳記、項目識別碼、記錄映射、釘選及提交內容均加密。獨立已驗證金鑰檢查記錄，即使保管庫為空也會拒絕錯誤還原主金鑰。

每筆加密記錄使用新的隨機 12-byte nonce 及 16-byte 驗證標籤。AAD 包含格式／域標記及保管庫識別碼；舊打包記錄另綁定實體 part 識別碼及位元組偏移。格式 2 密文雜湊透過加密記錄映射驗證，每個分塊使用保管庫專屬驗證域。中繼資料、日誌、提交事件及金鑰包裝各用不同域。讀取在回傳明文前驗證每筆記錄。損壞但無待寫變更的快取，只有完整來源物件通過驗證才可取代；沒有真確來源副本就會失敗。

## 布局及分割

所選儲存資料夾包含 `vault.json`、格式 2 不可變 `parts/<ciphertext-sha256>.mfe` 密文物件（舊格式 1 使用隨機 part 識別碼），及加密 `commits/<random-id>.mfe` 事件。獨立本機快取包含這些加密物件、加密 `journal.mfe` 及公開保管庫設定副本。儲存與快取根目錄須分開且不重疊。根目錄及受管物件路徑拒絕符號連結、Windows junctions／reparse 路徑，防止快取別名指向雲端物件。

格式 2 實體 part 包含一個固定大小已驗證分塊，最後一塊可較短。實體上限包括框架、nonce 及標籤，範圍為 1 KiB 至 90,000,000 bytes，預設 10 MiB。舊格式 1 保留最多 64 KiB 的打包記錄。增量修改重用未改密文分塊。主機將使用者選擇單位換算成精確位元組。`SetPartSize` 更改新檔及之後修改檔案的策略；現有檔案保留原上限，直至資料／長度變更或明確 `ResplitAsync`，所有新實體 part 均符合新上限。重新分割發佈替代版本而保留舊物件。引擎不執行雲端垃圾回收。

稀疏增長只記錄長度，不建立所有零分塊。缺失分塊讀為零。縮小檔案移除後續記錄參照，並清除保留的邊界分塊，避免之後延伸時重現已丟棄位元組。

## 命名空間及多裝置發佈

路徑遵循不分大小寫 Windows 查找規則、保留顯示拼寫，並拒絕路徑穿越、空元件、無效字元、結尾點／空格及 Windows 保留名稱。引擎提供建立檔案／目錄、枚舉、中繼資料、隨機偏移讀寫、長度變更、刪除及原子命名空間重新命名／取代。穩定項目 ID 為既有開啟控制代碼保留已刪除或取代內容，直至租約關閉。

原控制代碼仍開啟時還原已刪除項目，會建立另一個有效身分。原控制代碼的讀寫、長度變更及刪除只作用於原來已刪除項目。沒有有效路徑的孤立寫入不安排靜置自動版本；最後租約釋放孤立項目及殘留到期標記。把歷史版本還原到同一有效項目，保留目前項目行為。

並行裝置重播復活仍被開啟持有的已刪除項目時，亦採用相同分離。身分協調透過一般加密命名空間提交記錄及發佈，因此後續裝置重播及重新開啟保留新有效身分。靜置版本排程區分真正孤立物件及有效項目；關閉孤立項目不會清除有效項目的待處理版本。

每次本機沖寫產生有唯一識別碼及所觀察父節點的不可變加密提交。加密事件包含命名空間變更、預期舊版本及祖先目錄快照。各裝置發佈自己的事件，不覆寫單一 manifest 或依賴跨裝置檔案鎖。重播按提交 DAG 決定性排序。並行修改在命名空間保留兩個不同穩定身分版本；衝突副本顯示 ` (conflict ...)` 後綴。並行刪除不會暗中隱藏仍有後代修改，重播會還原必要祖先目錄。同步收到遠端刪除後，既有開啟控制代碼仍可用。

接收裝置在接納新版本前驗證快照中繼資料及參照物件可用性。內容在取回或還原時驗證；列出歷史不會預先取回歷史內容。不完整、缺父節點或未驗證提交保持待處理，最後可用命名空間繼續可用。parts 先上傳，提交後發佈。發佈使用暫存檔再取代，報告本機耐久性前先沖寫檔案資料。

## 離線行為及耐久性

`FlushAsync` 先寫入加密內容及命名空間日誌並沖寫磁碟。來源資料夾缺失或拒絕發佈時，成功本機沖寫保留排隊提交，並透過 `VaultSyncStatus` 顯示失敗，不聲稱供應者同步。之後同步發佈排隊物件及匯入完整事件。成功沖寫後程序突然退出，會從加密日誌復原命名空間及排隊事件。

`SetPinnedAsync(path, true)` 在儲存釘選前取回及驗證全部必要加密內容。資料夾釘選涵蓋未來後代；根釘選涵蓋全保管庫。移除釘選不丟棄未儲存變更。`EvictCache` 保護已釘選、開啟、孤立但開啟、已更改及未發佈內容，移除安全本機密文物件前先驗證來源副本。中繼資料保留於日誌。沒有來源副本的未釘選內容在離線要求時清楚失敗。

狀態描述對所選本機資料夾的存取及發佈。OneDrive 或 Google Drive 自行執行遠端傳輸；引擎不能斷言它們的伺服器已收到本機變更。此格式會暴露密文大小、物件數目及活動時間，尚未實作填充或供應者層流量隱藏。程序崩潰測試涵蓋成功沖寫，但不模擬突然斷電或所有檔案系統／供應者耐久行為。檔案 ACL、NTFS 替代資料流、硬連結、位元組範圍鎖及雲端垃圾回收不在目前核心介面範圍。

歷史及傳輸子程序收到已關閉、隔離的標準輸入。標準輸出、標準錯誤及程序退出共用既有 60 秒取消期限。取消終止自有子程序樹，並作有界結束清理而不取代原操作失敗。還原本機變更與之後背景歷史／傳輸完成不同；還原成功本身不證明同步。

## 重現檢查

```sh
dotnet run --project native/MaterialFileEncryptor.Core.Tests -c Release
```

獨立執行器只用 .NET SDK，涵蓋隨機存取、稀疏／截斷資料、重新命名取代與穩定控制代碼、只改大小寫重新命名、憑證與金鑰還原、明文洩漏掃描、Windows 路徑驗證、打包實體上限及重新分割、防竄改與已驗證來源回復、程序退出日誌復原、來源中斷及排隊發佈、決定性並行修改副本、不完整新版本、持開啟控制代碼時遠端刪除、遞迴刪除目錄時後代修改、釘選／快取移除規則，以及根目錄／受管子項符號連結拒絕。Windows Explorer／WinFsp 行為需要另作 Windows 主機檢查。
