# 加密儲存庫備份、還原及同步

直接喺主要導航開啟 **Docker Hub 儲存**。登入、目的地設定、同步、排程同還原控制會放喺最上方。填入現有 Docker Hub 儲存庫，格式係 `namespace/repository`，並選擇預期嘅公開或私人可見性。認證由主程序透過 Docker Desktop 憑證儲存處理，介面唔會收到憑證。儲存設定唔等於已經上載。整理分段同映像匯出仍然保留喺備份控制下方。

## 引導登入同明確可見性

面板提供官方 Docker CLI 裝置登入流程，先驗證已儲存嘅登入。未有登入時，顯示暫時裝置碼，並提供明確嘅複製、開啟授權頁、取消同重試控制。授權頁固定係 `https://login.docker.com/activate`。密碼同存取權杖唔會輸入呢個應用程式，原始 CLI 輸出亦唔會傳入介面。CLI 完成後仍然要驗證憑證儲存，先可以顯示成功。

新空白設定明確預設公開；舊設定冇可見性欄位就維持私人。讀取同發佈之前會檢查實際名稱、可見性同寫入權限。儲存設定唔會更改供應商可見性，亦唔會自動同步。公開密文同快照資料可被其他人下載，物件大小、識別碼同發佈時間唔會因加密而隱藏。免費公開儲存庫仍受供應商現行限制同公平使用條款約束。

狀態機、介面控制同實體封裝資源路徑已有針對性來源測試。下載嘅 `v1.845.1` 主控台橋接已通過編譯、真正 ConPTY 啟動、固定合成子程序取消同正常結束驗證，見[來源綁定證據](../../evidence/registry-login-native-81cb8ca5.json)。呢啲結果唔代表真正裝置授權、安裝後行為或者之後修改嘅導航已驗收；實際 GUI 證據另外記錄喺交接文件。

## 備份同多部電腦同步

**立即執行加密同步** 會先發現不可變快照，驗證清單同密文摘要，再加入缺少嘅物件。唔會覆寫已存在但內容唔同嘅物件。寫入之前一定先取得原生來源擁有權。原生引擎按加密交易祖先關係重播，兩部電腦同時改檔案時，沿用確定性衝突副本保留版本。

開住或者掛載緊嘅保管庫會喺原生交易邊界凍結快照，暫存所需密文時可以繼續之後嘅寫入。租約會保護快照引用嘅分段，直到暫存完成。鎖定保管庫沿用原有來源保留機制。快照包括加密設定、交易歷史、活動同引用分段，唔包括即時日誌或者憑證。

每次發佈都有獨立參照同已驗證摘要，唔會靠共用最新標籤決定邊部電腦贏。每部電腦保留自己嘅來源同快取；同步唔等於任何編輯器都可以即時共同編輯。

Docker Hub 可以將密文物件下載重新導向官方 HTTPS 內容傳送主機。物件讀取最多跟隨三次重新導向，只接受同一摘要綁定路徑，共用一個逾時限制，亦唔會跨來源傳送認證或 Cookie。清單同上傳要求維持原有來源限制，下載內容仍要符合確切長度同 SHA-256。驗證中斷時，目的地可能已保留有效不可變發佈；應先檢查再繼續，唔好刪歷史或者盲目再發佈。詳情見[官方主機清單](https://docs.docker.com/desktop/enterprise/allow-list/)同 [OCI 重新導向要求](https://github.com/opencontainers/distribution-spec/blob/main/spec.md)。

## 自訂排程

排程預設關閉。可以設定 5 分鐘至 7 日嘅間隔，或者指定星期幾、本地 `HH:mm` 時間同 IANA 時區，亦可以揀錯過時補跑一次或者跳過，以及重試延遲。夏令時間跳過嘅本地時間唔會憑空執行；同一個已執行嘅重複時刻唔會再跑一次。

安裝版可以選擇登記目前使用者嘅 Windows 工作，每五分鐘檢查到期同步。工作用真正安裝路徑加 `--registry-sync`，只喺已登入時以最低權限執行，唔會儲存登入密碼、喚醒電腦或者代為登入。背景啟動唔會自動解鎖或者掛載保管庫；如果程式已開，會交畀現有程序處理，唔會搶走前景。

啟動時會核對已啟用背景排程同自己擁有嘅工作，並即時檢查到期同步。除咗執行檔同使用者身分，工作亦必須保留已啟用嘅五分鐘觸發器。日曆重試會保留原本排程時刻。另一個保管庫嘅背景工作仍然屬於嗰個保管庫；可以選取顯示嘅擁有者，檢視進度或者取消工作。

更新或者移除工作之前，必須核對記錄嘅身分、執行檔、使用者同參數。被改過或者擁有權唔明嘅工作會保留。登記未完成會清楚報告，手動同步仍然可以使用。真正安裝後嘅排程執行需要獨立驗證。

## 喺另一部電腦還原

未有本機保管庫都可以儲存目的地、列出快照同還原。明確揀選摘要，再透過原生資料夾選擇器揀上層資料夾。程式會建立全新獨立資料夾，驗證密文清單，最後先寫入設定。現有保管庫唔會被取代或者自動切換。結果會顯示真正還原位置，之後喺正常解鎖流程揀嗰個資料夾；原有金鑰驗證仍然保留。

還原只係密文複製，唔等於已解鎖或者已原位回退。中途中斷留下嘅未完成資料夾應保留檢查，下次用另一個全新目的地，唔好為咗重試而覆蓋可用資料。

程式會跨重啟保留真正還原位置同複製是否完成，部分副本清楚標示未完成。進度顯示已處理密文檔案及位元組；上載準備數量只代表已準備資料，唔會當成所有網絡資料已經送達。鎖定儲存同步會清楚顯示原生重播延後，之後須明確解鎖先檢視合併嘅檔案變更。

## 取消、限制同驗證

取消會要求網絡同原生快照停止，再等原有工作真正收尾。租約釋放未核實會保留擁有權，唔會繼續另一輪同步或者假裝安全退出。中斷上載可能留下未引用物件，但冇已驗證清單就唔會當成完整快照。重試前會重新發現已發佈版本。

目前客戶端限制每個物件 1 GiB、每個快照 100 GiB 同 100,000 個物件，單次目錄讀取最多 1,000 個快照參照及 64 MiB 中繼資料。超出限制會報未完成，唔會交一份缺漏清單扮成功。未實作遠端歷史刪除或者自動垃圾回收。

針對性測試會先喺獨立 Ubuntu WSL 用合成資料驗證真正 OCI 登錄協定、同時發佈、摘要、排程、還原同租約恢復。原生測試另外驗證加密快照同衝突保留。真正封裝介面、掛載磁碟、安裝後工作、正式 Docker Hub、下載及安裝更新都要各自驗收；來源測試同 WSL 成功唔會冒充呢啲證據。

呢個分類冇產品 HTTP API，Postman 集合唔適用。最新證據同未完成項目請睇交接記錄。

## 綁定確切版本嘅衝突審閱

桌面通訊只會透過目前選定保管庫提供 `listRegistryConflicts` 同 `resolveRegistryConflict`。分頁有上限，衝突同版本識別碼只接受固定十六進制格式。套用前會固定已檢視識別碼，再開主程序管理嘅本地化確認，預設取消；之後再次核對保管庫、關閉狀態同 registry 工作狀態。原生重播仍須原子比對確切版本；檢視過期就必須重新整理同選擇。

刪除意圖用獨立交易識別碼表示，保留嘅即時版本為 null，唔會扮成仍存在嘅檔案。歷史分歧復原必須回傳兩條實際而不同嘅路徑；缺少或者格式不符都保持未核實。取消確認唔會發送原生改動要求。原始碼檢查唔代表封裝或者掛載驗收已完成。
