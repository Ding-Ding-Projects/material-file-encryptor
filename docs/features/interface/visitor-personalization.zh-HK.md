# 網站訪客個人化

訪客連接層會在說明網站自己的設定內掛載共用個人化控制。使用者毋須配對桌面程式，亦不會操作加密磁碟。語言、英文及廣東話各自的趣味程度、主題、密度、字型、動態效果、標誌、旁白聲線、注意力模式及本機排程都使用訪客自己的瀏覽器狀態。

## 儲存及私隱

設定以獨立訪客前綴儲存在目前瀏覽器來源，供各說明路由共用。連接層不會讀取桌面設定，亦不會將舊有成功或搜尋訊息滑桿當成語言偏好。如果儲存被拒絕，之後的修改仍可在本頁記憶體使用；通知會清楚說明重新載入後將會失去修改。此連接層不會套用私人用詞。

## 排程及能力界線

本機排程使用共用的時區、日期、星期、跨午夜及優先次序驗證。外部來源必須由主機明確提供可信能力；沒有能力時不會發送來源請求，而本機排程仍然可用。設定或核對模式解鎖憑證亦需要明確的存取能力。缺少能力絕不等於通過驗證。

## 整合及待驗證項目

`mountVisitorPersonalization(container, options)` 回傳 `store`、`apply`、`getSettings`、`open`、`addLocalSchedule` 及 `destroy`，另有共用旁白、外觀及歷史管理器。`onChange(settings, metadata)` 提供標準有效設定及實際持久儲存狀態。網站外殼負責路由掛載、公開文字、受限制操作及版本來源。歷史憑證和破壞性操作確認由獨立能力提供。

共用畫面部分巢狀編輯器仍使用原生控制。完整註冊元件、每個下拉選單的正規表示式篩選、進階外觀能力及實際瀏覽器互動仍未驗證。原始碼檢查只證明獨立語言偏好、儲存備援、本機排程及缺少能力時的拒絕行為，不能代替畫面或旁白聲音驗收。

主機提供與本機存取相同的私人歷史管理器，以及明確的設定檔驗證狀態。只有設定檔及歷史均已解鎖時，每次實際設定修改才會新增一次歷史快照。沒有修改的更新不會產生事件。歷史寫入失敗會通知使用者，但不會撤回已套用的設定。

模式啟用狀態的修改必須先成功設定或核對憑證，取得一次性授權。中央設定處理同樣限制匯入、重設及歷史還原。模式啟用時不能直接重設；使用者必須明確核對憑證並關閉模式。嘗試修改會消耗授權；設定檔中途鎖定亦會使授權失效。
