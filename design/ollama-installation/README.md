# Managed Ollama installation reference

This bounded reference uses the actual runtime-region renderer and registered Material Web buttons, outlined text field and linear progress component. It is a synthetic design reference, not installation or rendered production evidence. Open `reference.html` through the repository's local static preview route. `inventory.json` lists deterministic states and required capture tuples.

The primary action installs the official complete command-line archive into application-managed storage. It does not register the vendor desktop application, start a runtime, download a model, change global PATH, request elevation or stop another process. Verified `installed-stopped` is distinct from API health. Start remains a separate, explicitly confirmed action. Existing installations and occupied endpoints remain host decisions.

The host owns `runtimeInstall`, `runtimeInstallStatus`, `runtimeInstallCancel` and the `runtime-installation` event. Each snapshot carries operationId, phase, receivedBytes, totalBytes, cancellable, outcome, reason, version, architecture and installed. The renderer rejects backwards phases, decreasing download bytes and retired operation identifiers. Terminal outcomes are sticky for their operation. Pending admission prevents duplicate clicks; cancellation reports stopping until the host returns its result. Atomic registration disables cancellation. Installation state remains separate from catalog, model pulls and chat events.

Controls are updated in place. When an initiating action becomes disabled, focus moves to the runtime heading; language changes preserve enabled-control identity and focus. Bilingual visible text stacks English and Cantonese. Accessible labels are plain complete text. All runtime actions retain at least 48 CSS pixels height. Theme colors use semantic component properties. Runtime discovery runs independently of model catalog refresh.

The synthetic checks exercise the actual renderer through a minimal DOM. They prove state transitions, not layout, browser custom-element behavior, native execution or assistive-technology behavior. Required real evidence remains open: normal/minimum viewports, English/Cantonese/bilingual, light/dark, 100/125/150/200 percent scales; keyboard order and disabled-action focus; progress semantics; event recovery after navigation; cancellation and retry against the actual host; archive integrity, complete extracted-tree verification, installed-path verification and a separately verified start. Bind each genuine capture to its source and built executable/resource hashes. No user profile, installer, model or real process is touched by the reference.

Active installation polling re-arms after every settled read, including identical or stale snapshots. Only one status read runs at a time; terminal state and disposal stop polling. Connection settings uses a registered outlined button with explicit expanded state and ownership of its hidden region.
