# Local tools workspaces

## Converter

Choose source files, review the detected source preview, choose a compatible format from its category, review conversion options, then choose the output destination. The four tabs retain state when switching. Left/Right and Home/End move between tabs. Every category and the option list has the shared local search with an anchored expression builder. Disabled formats keep their unavailability explanation.

Conversion remains local through the existing bounded adapter service. Source files are unchanged. Destination replacement still invokes the existing confirmation flow. Queue history is loaded in pages of 50 with non-overlapping refresh requests. Each item exposes state, progress and its existing pause, resume and cancel actions. A pending picker cannot repaint a destroyed workspace.

## Local models

Model Store, Pull cart, Local chat, Profiles and Help are distinct keyboard-navigable panels. Runtime and catalog maintenance is grouped under a disclosure. Search uses the shared worker-bounded expression builder. Model selection is explicit, model facts are retained, and each queued download displays byte progress. Catalog refresh, downloads and runtime actions retain their existing confirmation and authenticated native bridge boundaries. Merely visiting a panel never starts a download or server.

## Server preparation

The preparation view separates the bounded version list, current selection and operation cards. Download byte progress is labelled as unverified until the existing SHA-256 verification completes. It continues to state that server startup, other execution targets and license acceptance are not provided.

## Verification

Focused synthetic component checks cover adapter-category inventory, actual control construction, tab navigation, existing native payloads and teardown. These checks do not prove built layout, installation, runtime services, network availability or real model downloads. Built visual acceptance remains separate.

## Rendered provider responses

Local model answers and saved assistant messages use the existing bundled DOM-only Markdown renderer. Headings, paragraphs, emphasis, lists, tables and fenced code render as content. User and system messages remain literal. JSON model metadata and profile preflight results remain exact data. Provider HTML is never interpreted; provider images have no asset catalog and never load; executable, relative, data and credential-bearing links do not become external anchors. Allowed HTTP(S) links open only on explicit activation with no opener or referrer. Task checkboxes are disabled registered controls.

Streaming uses one 60 ms render timer for the active response, preserves partial code fences and formatting delimiters, and flushes at completion, cancellation or error. Events arriving before the native request response are isolated by operation identity, bounded to four pending identities and 1 MiB of text per identity, and only the returned operation is adopted. Switching saved sessions, regenerating or destroying the surface invalidates stale rendering. Partial results remain visible when an operation stops or fails.

Formatting is bounded to 262,144 characters, 2,048 lines, 8,192 characters per line, 16 nested structures and 128 opening link brackets per line. Content beyond those formatting limits is disclosed and shown in full as literal text, rather than silently truncated or recursively parsed. These presentation bounds do not relax the native service response limits.

Adversarial component coverage includes source HTML, executable and credential-bearing URLs, remote images, code fences, tables, task markers, deep nesting, oversized content, early events, split deltas, cancellation, disposal, and delayed saved-session reads. Synthetic checks do not establish real model execution or built visual acceptance.
