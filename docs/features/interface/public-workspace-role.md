# Public documentation workspace role

The public browser workspace opens documentation first. It provides documentation, changelog, preferences, local access, status, and authorized converter and local-model tools. Encrypted-drive file browsing, import, opening, export, offline actions, mounting, synchronization and locking belong in the installed application and are not exposed here.

## Client mediation

The browser adapter accepts only feature requests for its explicit personalization, status, converter and local-model action lists. It rejects primary drive operations and unsupported feature namespaces before reading connection status or sending any network request. The installed application's server API remains unchanged. Pairing still requires loopback, a one-use code and explicit desktop approval. Disconnection clears credentials and the local tool views.

## Confirmation and page lifetime

Output replacement, model deletion and session deletion use the shared in-surface two-key confirmation and full slider. An exact required phrase or model name remains mandatory where the consumer requires it. Approval resolves at the final Confirm action. It does not display operation-completed or Done states before the caller actually performs its action. No operation is approved by merely opening or cancelling the dialog. Session loss and every page departure cancel pending approval, and cached pages receive a fresh confirmation controller. The shared operation-execution mode remains unchanged for other workflows.

A cached browser navigation clears local pairing and private wording while retaining usable document controls. Normal departure disposes tools, timers, observers and shared controls. Saved legacy Files tabs are removed from open and restore inventories, preserving other saved tab, group and notification state.

## Verification

Focused behavioral tests cover rejection before network access, retained companion mediation, real two-key and slider interaction, exact-text refusal, cancellation, owner abort and legacy-tab migration. Server tests retain installed-context API coverage. Source checks do not establish built browser layout, live pairing, native tool acceptance or deployed behavior; those remain separate verification.

## Paired preferences and capability limits

Saved external schedule reads forward the selected source and stable schedule identifier to the installed host. Installed font names are available while paired. Shared mode changes are read every five seconds with an overlapping-request guard; obsolete responses from a disconnected or replaced session cannot update preferences. An unchanged snapshot does not create another history entry.

Home Assistant credential storage and clearing, native font metadata scanning, native image normalization and runtime-port configuration remain desktop-only. The browser does not extend either allowlist. Configure these capabilities in the installed application; local browser image normalization uses its existing worker. Credential values are never fetched back into the browser. The connection view states these limits explicitly.

Settings guidance opens the bundled article and concept in the documentation reader and registers its commands. History pruning requires both authenticated local access and unlocked private history, the two-key confirmation and full slider, and revalidation at the mutation boundary. Losing either authorization cancels pending approval. The frame keeps navigation and open-work tabs stationary while the selected content scrolls. New profiles open documentation only; opening another destination creates an actual work tab.
