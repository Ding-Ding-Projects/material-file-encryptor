# 帳戶同儲存庫發布

已安裝桌面使用 GitHub CLI 進行瀏覽器登入、帳戶發現、選擇活躍帳戶同逐個帳戶登出。憑證由 `gh` 管理，留喺作業系統憑證儲存庫。服務會拒絕純文字憑證設定，移除繼承嘅持有人憑證環境覆寫，只回傳帳戶名稱同活躍狀態，亦唔會要求呈現層提供憑證。指定帳戶刷新目前會喺任何指令之前停止，因為 CLI 刷新交易使用可變嘅活躍帳戶狀態；可用嘅帳戶更新途徑係重新透過瀏覽器登入。

發布準備由原生選擇器揀選專案資料夾開始。選擇已登入嘅活躍帳戶、可用嘅個人或組織擁有人、儲存庫名稱、可見性，同埋複製並上載或分叉路線。準備會固定一個冇未提交改動嘅來源提交版本。複製並上載將會傳送該版本嘅完整已提交歷史；分叉會保留上游可見性，唔會傳送本機改動。

## 綁定帳戶嘅發布

普通 `gh` 活躍帳戶途徑可能喺指定帳戶嘅鑰匙圈憑證缺失時，退返共用活躍憑證。隔離中繼資料設定同重複身份檢查都唔能夠消除呢個競爭條件。發布改為由專用嘅特權產品子程序，使用受支援、只查安全儲存嘅指定帳戶查詢。憑證留喺操作私有記憶體，只透過產品自己啟動嘅提供者指令同固定 Git 憑證協助程式嘅環境傳送。憑證唔會回傳呈現層、持久儲存、匯出、放入指令參數或診斷記錄。指定憑證缺失會喺發布之前停止，絕對唔會改用另一個活躍帳戶。

呢個邊界根據 [GitHub CLI 2.102.0 指定安全儲存指令](https://github.com/cli/cli/blob/v2.102.0/pkg/cmd/auth/token/token.go#L67)、[逐帳戶鑰匙圈查詢](https://github.com/cli/cli/blob/v2.102.0/internal/config/config.go#L305)，同埋 [Git 憑證協助程式](https://github.com/cli/cli/blob/v2.102.0/pkg/cmd/auth/gitcredential/helper.go#L108)。喺任何改動之前，服務會用已綁定憑證驗證提供者目前嘅使用者。外部活躍帳戶切換唔會取代已擷取嘅身份。

## 安全同復原

產品只使用建置產生雜湊收據入面嘅絕對套件執行檔。每次執行之前，都會核對固定版本、精確相對路徑、一般檔案身份同 SHA-256。Git 協助程式使用 POSIX shell 引號處理已驗證路徑，唔會依賴 `PATH`。兩個工具都必須存在而且冇變；工具缺失或改動就會停止。複製並上載先建立臨時裸複本，再將已檢閱版本上載至 `main`，並要求目的地屬性讀回同精確版本證明。服務唔會強制推送、重寫歷史或切換來源分支。

已協調收據合約使用 schemaVersion 1，並固定 gh/bin/gh.exe 同 git/cmd/git.exe 路徑、版本同 SHA-256 欄位。舊 schema 鍵同未知 schema 版本會拒絕。建置來源提交 9b6024f2ad09063feae7ef545a9aae9523dc1d8d 嘅實際產生收據保留為測試樣本，只證明格式綁定，唔會聲稱已安裝驗收。

取消要求會跨越檔案系統、憑證同指令等待保持有效。被取消嘅在途提供者指令仍然可能已經改動目的地。結果會分開列出已確認完成操作同曾嘗試操作，只要改動可能已開始，就要求檢閱目的地。臨時複本會移除，已建立目的地則保留畀用戶檢閱。服務唔會用自動刪除聲稱已經回復發布。

操作結束時會清空私有擷取緩衝區，並釋放子程序環境參照。JavaScript 字串儲存同作業系統程序環境唔保證實體清除，而有足夠權限嘅程序檢查工具可能讀到運行中嘅子程序環境。呢個係明確傳輸限制，唔係硬件隔離承諾。開發測試使用合成擷取介面，冇讀取目前用戶嘅憑證，亦冇執行真實登入或發布指令。

所有序列化帳戶操作都會跨越指令同檔案系統空檔保留取消代次。取消之後唔會再開始下一個指令，已取消結果亦唔會報成功。已開始嘅指令可能改變帳戶狀態，取消唔能夠保證回復外部狀態。

帳戶改動同發布操作只供桌面使用，瀏覽器介面唔可以公開呢啲操作。所有指令參數都係分開嘅陣列，唔經 shell；目的地識別碼有界限同驗證。登入可能需要用戶完成 CLI 瀏覽器流程。注入式本機測試未有驗證實際瀏覽器登入、憑證管理器持久儲存或提供者改動。

## 驗證

`test/forge-workflow.test.js` 同 `test/forge-transport.test.js` 使用合成指令回應、假憑證子程序同可棄置資料夾。測試涵蓋外部帳戶切換期間嘅指定帳戶綁定、指定鑰匙圈缺失時停止、改動之前同擷取期間取消、部分改動結果、擷取錯誤遮蔽、協助程式路徑引號、套件雜湊、精確確認同版本證明。測試唔會發布儲存庫，亦唔會使用現有用戶帳戶。真實帳戶、安全儲存、發布同已安裝套件驗收，仍然要另外執行先可以驗證。

## 受保護新增帳戶可用狀態

新增帳戶目前會喺呼叫 CLI 登入之前停止，因為該途徑可能回退到明文儲存。重新授權帳戶亦未開放。已經存在於作業系統受保護儲存嘅帳戶仍支援綁定帳戶發佈。保證受保護嘅新增帳戶交易屬於另外未完成嘅工作；開發期間冇執行真實登入或目前憑證命令。

非登入可行性探測使用固定 GitHub CLI 執行檔、自有空白設定、刻意無效嘅公開用戶端識別碼同明確非秘密授權標記。結果係 OAuth 錯誤類別（結束碼 1）。冇執行有效裝置流程或目前憑證查詢。呢個結果只證明端點可連接。來源檢查確認空白 Authorization 標頭本身唔會阻止 CLI 憑證查詢，而明確非空白標頭會；根部登入檢查會喺存在明確環境憑證時直接通過。受保護新增帳戶仍然關閉，等候經審查嘅產品自有 OAuth 用戶端同交易實作。

另外嘅受保護帳戶提供者已實作，入口要求注入經審查嘅用戶端資料。裝置交易只接受產品自有、已啟用裝置流程嘅公開用戶端，驗證回傳帳戶身份，再透過版本比較寫入只供原生程序使用嘅 `forge-account:` 空間。現有 CLI 鑰匙圈帳戶保持原狀。裝置請求內容留喺特權 stdin 緩衝區；新憑證只提供畀自有身份查詢子程序環境，之後經作業系統受保護儲存保存。實作唔保證 JavaScript 字串可實體抹除。受保護寫入已提交後收到取消會明確回報。提供者已透過原生工作流程工廠接駁，但未設定產品註冊之前新增帳戶仍不可用；合成測試唔代表真實新增帳戶成功。

帳戶記錄以 `sourceKind` 區分 `gh-keyring` 同 `protected-product`。未改動嘅 CLI 鑰匙圈帳戶使用 null 嘅 `credentialRevision`，產品自有帳戶就使用受保護 UUID 收據。已選擁有人、啟用帳戶、登出同重新授權操作都帶埋來源及版本。準備發佈會固定呢兩個欄位；確認資料必須同計劃相符。同名帳戶嘅來源係獨立記錄，來源有歧義時缺少資料會停止。產品發佈只會將完全相符嘅受保護版本放入隔離自有子程序設定，再驗證身份，唔會回退到 CLI 帳戶。
