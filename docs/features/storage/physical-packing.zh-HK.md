# 加密分段實體打包

新保管庫預設每個實體分段上限為 80 MiB，即 83,886,080 bytes，已包括驗證加密記錄的額外資料。最高可設定 90,000,000 bytes。每個加密記錄仍然最多 64 KiB，並非把整個 80 MiB 檔案載入明文記憶體。

## 寫入及關閉

每次檔案系統寫入都先完成加密物件及本機日誌，才確認持久儲存成功。複製期間可能暫時產生很多細分段。最後一個可寫入描述符真正 Close 後，背景工作才打包；Cleanup 並不代表記憶體映射已放手，兩個寫入者亦必須全部關閉。

背景工作固定原有記錄快照，在命名空間鎖及檔案系統回呼鎖以外讀取、驗證和打包。採用新記錄之前會重新核對路徑、檔案身分、版本、寫入者世代、活動寫入者及目標上限。期間若有修改、縮短、改名、刪除或重建，就不會蓋過新資料。

完整替代記錄表透過原子日誌快照保存，並清除已被取代的疊加記錄。所有新加密分段必須先完成。採用前取消或中斷，原有資料仍有效；採用後中斷，新資料已持久保存。中途產生而未引用的密文保留，來源儲存不會自動清除歷史物件。

## 現有磁碟遷移

原生命令 `startPacking` 接受可選 `path` 及 `partSizeBytes`。沒有路徑時會排程所有現有檔案，並保存新預設上限；指定路徑則只處理檔案或子目錄。預設目標是 83,886,080 bytes。使用 `operations` 查進度及 `cancelOperation` 取消。

排隊的檔案身分及目標上限會寫進加密日誌，重開後可以繼續。已完成的打包版本會略過。仍有寫入者的檔案留在隊列，關閉或定期維護時再處理。命令完成不代表所有寫入者已關閉，請同時查看 `pendingPackingFiles` 及 `activeWriters`。取消不會撤銷已採用的完整檔案，並會持久暫停自動打包；定時維護及關閉寫入者都不能自行重開。再次明確執行 startPacking 才會繼續。狀態提供 paused，診斷提供 packingPaused。

## 發佈及狀態

來源發佈逐批處理已持久保存的提交，在核心鎖以外驗證及複製每個密文分段，全部完成才寫入提交中繼資料，最後只確認該批實際已上載的提交。期間新增的提交不會被誤清除。來源已寫入但本機尚未確認的情況可安全重試。來源離線時，本機持久資料保留。

同步先在鎖外取得來源資料，重建命名空間前再保存期間發生的本機修改。檔案 Flush 及閒置版本保存只負責本機持久性，關閉檔案不會同步打包整個大檔案。

`storageDiagnostics` 提供目標上限、待打包檔案、活動寫入者、目前引用分段與實體 bytes、只屬歷史的分段與 bytes，以及暫存分段數目。無法在本機或來源觀察的物件只計數、不計 bytes。歷史仍然保留，所以遷移期間總用量可能增加，不能把目前分段數當作已釋放空間。

## 驗證界線

原生合成測試涵蓋雙寫入者、匯出快照、同時修改、改名、刪除重建、採用前取消、快照前後中斷、縮短後稀疏增長、慢速來源及確認重試。大型測試超過兩個 80 MiB 上限，使用 64 KiB 與 1 MiB 寫入並核對 SHA-256。合成測試不代表已驗證安裝版 Explorer 複製、真實磁碟遷移或程序記憶體峰值；這些需要另外記錄實際執行證據。
